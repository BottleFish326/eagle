# ADR-025：平台路径身份与离线根目录语义

- 状态：Accepted
- 日期：2026-08-19
- 对应：P2-08、P2-A08、P2-A09、P2-A12

## 背景

同一份素材库可能位于 APFS、NTFS、ext4、移动硬盘、网络盘或同步目录。平台对大小写、Unicode 组合形式、保留名称、路径长度和符号链接的处理不同；扫描中途掉线还可能使一次不完整遍历看起来像“素材全部删除”。应用不能为了统一这些差异而重命名、复制或重排用户文件，也不能把某次扫描快照提升为第二真相源。

## 决策

1. 配置根先由操作系统 `canonicalize`，再按目标平台逐组件比较。Windows 比较键执行 NFC 和小写归一；macOS 执行 Unicode 规范分解但不假设卷是否大小写敏感；Linux 保留原始 Unicode 形式和大小写。
2. 平台比较键只用于身份、碰撞和测试，不改写展示路径、素材路径或 Sidecar。Windows 保留名、禁用字符、尾随点/空格和传统 260 UTF-16 单元长度只产生可移植性诊断，不在其他平台隐藏或修改合法文件。
3. 根目录必须绝对、UTF-8、当前可访问且互不重叠。重复、包含或被包含都明确拒绝；配置不允许启用符号链接跟随。
4. 扫描固定使用 `follow_links(false)`。遇到符号链接时只输出“已跳过”问题，不进入链接目标，因此循环不会无限遍历，链接目标也不会重复计数。
5. 非取消扫描在批次发布后和权威完成前重新执行根目录访问检查。根变为缺失、非目录、无权限或不可用时，本次扫描失败且不得成为权威结果；桌面目录恢复扫描前记录，并把根切换为对应离线状态。
6. 文件监听启动或运行失败也携带实时根访问状态。前端停止该根监听，显示降级提示；状态不明确时重新读取根配置的实时访问视图。
7. P2-A12 使用同一 `p2_platform` Rust 测试集在 Ubuntu、macOS、Windows 托管运行。纯规则夹具验证跨平台差异，原生夹具验证 Unicode 路径原样扫描和根重叠；需要权限或符号链接能力的测试按平台条件运行。

## 影响

- 拔盘或撤权不会把临时空遍历提交为素材删除；已发布到 UI 的临时批次会由失败对账恢复。
- macOS 卷的实际大小写模式仍由操作系统 canonical path 决定；不把“默认 APFS”误当作所有卷的固定属性。
- 传统 Windows 长度诊断不是拒绝规则。完整长路径读写仍必须在 Windows 运行时矩阵验证。
- 网络盘和同步盘不按厂商实现特殊数据库状态机；统一依赖实时目录可访问性、监听失败和下一次完整扫描收敛。

## 不采用

- 为了跨平台兼容自动改名、复制或移动素材；
- 跟随符号链接后用全局 visited 数据库消除循环；
- 根掉线时把不完整扫描当作权威空目录；
- 假定所有 macOS 卷大小写不敏感，或在 Linux 上折叠大小写；
- 用持久化素材索引记录卷在线状态。
