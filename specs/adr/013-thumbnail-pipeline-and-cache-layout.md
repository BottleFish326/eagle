# ADR-013：缩略图管线与缓存布局

- 状态：Accepted
- 日期：2026-08-14

## 背景

P1-06 需要为 PNG、JPEG、WebP 和 GIF 提供可用于素材网格的缩略图，同时继续满足文件系统真相源、原始素材只读、派生缓存可删除以及单文件故障隔离等约束。完整像素解码属于 CPU 和内存密集操作，不能阻塞 Tauri 异步命令或素材扫描；缓存清理也必须有明确边界，不能依赖用户传入任意目录。

## 决策

1. 缩略图只在视图显式请求某个已扫描 `AssetRecord` 时生成。扫描和查询不预生成缩略图，P1-07 的视口观察器只请求可见卡片。
2. 使用 `image` 0.25.9 的最小 PNG、JPEG、WebP 和 GIF 功能集按文件内容识别并解码。GIF 只取第一帧；可用时应用解码器方向；长边超过请求尺寸时以 Triangle 过滤器缩小；缓存统一编码为 PNG。
3. 单次请求长边限制为 16–2,048 像素。源图单边限制为 65,535 像素，单次解码分配限制为 256 MiB；超过限制或解码失败时返回素材级占位结果，不影响其他素材。
4. 桌面端把解码、缓存读取和清理放入 Tauri 阻塞任务池。`ThumbnailService` 再使用进程内许可限制并发解码，桌面默认上限为 4。
5. 缓存键为 SHA-256，输入包含规范化运行时路径键、可选稳定 ID、文件大小、mtime、请求长边和解码器版本。原文件版本在排队后及解码后复核；版本变化时重新计算键，解码期间变化则不写缓存并返回 `source-changed`。
6. 缓存固定写入操作系统应用缓存目录下的 `thumbnails-v1`，按键前两个字符分片，文件名为 `<cache-key>.png`。写入使用同目录临时文件、文件同步和原子持久化。
7. 缓存目录包含固定保护标记。清理操作不接受路径参数，持有排他锁并同时校验规范父目录、固定目录名、非符号链接和保护标记，只删除并重建 `thumbnails-v1`。
8. 缓存命中前读取 PNG 尺寸以验证文件；损坏条目被移除并重新生成。旧版本或旧 mtime 的条目不会命中，容量回收和孤立条目清理由 P2-05 统一实现。
9. 元数据 IPC 返回 `ready` 或 `placeholder` 的结构化结果；PNG 正文通过 Tauri 原始二进制响应传输，避免把每个字节序列化成 JSON 数组。
10. `image` 固定为 0.25.9，因为该版本满足仓库 Rust 1.85 基线；升级依赖时必须同时修改解码器版本并执行缓存失效测试。

## 后果

- 首次扫描和查询不受缩略图解码阻塞，视口外素材不产生缓存；
- PNG、JPEG、WebP 和 GIF 可以共享一致的前端读取协议；
- 损坏、消失、不支持或解码期间变化的文件有可显示原因，不会中断批次；
- 删除缓存只损失派生 PNG，素材、Sidecar、Tag 和稳定 ID 均保持不变；
- 不同请求尺寸会生成不同缓存项，P2-05 需要对容量和孤立条目实施生命周期管理；
- P1-07 仍需实现实际网格、视口观察器、对象 URL 释放和占位视觉样式。

## 拒绝的方案

- 扫描时为全部素材同步生成缩略图；
- 把缩略图或缓存清单放入素材根目录；
- 以原始路径作为可由前端任意读取的文件协议；
- 把 PNG 字节序列化为 JSON 数字数组；
- 清理时递归删除调用方传入的任意目录；
- 将缓存键、缓存路径或内存索引视为不可重建用户状态。
