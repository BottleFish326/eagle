# ADR-012：查询语言与内存索引语义

- 状态：Accepted
- 日期：2026-08-14

## 背景

P1-05 需要让搜索栏、Tag 三态筛选和素材类型筛选共享一套可解释的语义。原型索引只能接收代码构造的查询对象，缺少扩展名过滤和正式解析错误；如果把无效表达式当成普通 Tag，界面会静默显示空结果，使用户无法区分“没有匹配”与“查询写错”。

## 决策

1. 查询文本先完整解析为 `AssetQuery`，成功后才执行；解析失败返回结构化错误、字节位置和相关 Token。
2. 普通 Tag 条件默认 AND，`any:(a|b)` 表示一个 OR 组，多个 OR 组之间仍为 AND，`-tag` 表示排除。
3. `namespace/*` 只匹配该命名空间的后代 Tag，不匹配不含 `/` 的命名空间自身。
4. 类型和扩展名条件各自在字段内部使用 OR，再与 Tag、排除和收藏条件使用 AND。
5. Tag 保持精确且区分大小写；扩展名统一为小写；类型与布尔值解析不区分大小写。
6. 内存索引维护 Tag、类型、扩展名和收藏倒排项。素材更新时先删除旧倒排项再添加新倒排项。
7. 查询结果按素材运行时键确定性排序，只通过 IPC 返回键、规范化查询和总素材数；完整记录继续由扫描批次提供。
8. 查询和索引均为可删除派生状态，不保存不可重建数据，也不读取或修改素材文件。

## 后果

- 搜索栏可以准确区分语法错误与合法零结果，并定位错误位置；
- 筛选面板可以根据规范化查询显示明确的活动条件；
- 多种条件可以稳定组合，测试清单不依赖 HashMap 遍历顺序；
- UI 需要保留扫描得到的素材记录映射，以查询返回键生成当前视图；
- 名称、备注和全文搜索不属于 P1-05，后续加入时必须扩展查询语言版本和兼容规则。

## 拒绝的方案

- 把无法识别的 `key:value` 自动当作 Tag；
- 解析失败后返回空集合；
- 为查询结果建立持久化数据库；
- 每次过滤都通过 IPC 重新发送全部素材记录；
- 在 UI 和 Rust 核心分别实现两套不同的布尔语义。
