# ADR-018：有界文件事件归一化与一致性扫描

- 状态：Accepted
- 日期：2026-08-15
- 关联：ADR-001、ADR-004、ADR-007、ADR-010

## 背景

P2-01 要求桌面应用在用户或外部软件修改素材目录时持续更新。平台监听 API 只提供提示而不是事务日志：事件可能重复、乱序、拆分或丢失；编辑器和同步工具常以临时文件加原子替换保存；队列溢出与半重命名无法安全推导最终磁盘状态。

如果直接把单个原始事件应用到内存索引，遗漏一次删除就会长期保留幽灵素材，错误配对重命名还可能破坏稳定 ID。监听事件也不能成为文件系统之外的第二真相源。

## 决策

1. 平台事件先转换为 `create`、`modify`、`move`、`delete` 或 `rescan-required`。纯访问事件忽略；只有同时包含旧、新路径的重命名才转换为 `move`。
2. 每个素材根使用一个递归监听线程。原始事件在 120 毫秒静默窗口内成批收集，连续事件最多等待 750 毫秒，单批最多 4,096 条；达到数量上限即视为可能溢出，不尝试猜测缺失内容。
3. 批内按路径确定性去重并折叠常见状态序列。创建后删除相互抵消，删除后创建视为替换修改，重复移动只保留一次。
4. `.tmp*`、`~$*`、编辑器交换文件和常见下载分片视为临时路径。临时文件移动到正式路径归并为目标 `modify`，不会把临时文件暴露为素材。
5. 半重命名、未知事件、监听错误、通道断开、批次溢出、空路径或素材根外路径一律产生带原因的 `rescan-required`。该事件的唯一路径是已配置且规范化的素材根。
6. 桌面端收到任一非空变更批次后，以 350 毫秒去抖请求该根的完整一致性扫描；已有扫描时每 500 毫秒等待，不并发启动自动重扫。
7. 完整扫描开始时只清除该根的运行期目录记录，再按磁盘和 Sidecar 重新建立。其他素材根、原始文件、Sidecar、配置和缩略图均不在清理范围。
8. 根目录管理中的刷新按钮明确表示“完整一致性扫描”。自动与手动扫描共用同一条受限命令，不接收任意扫描路径。
9. 本阶段只保证事件丢失后模型可由扫描收敛。利用稳定 ID 保持移动选择、孤立 Sidecar 诊断和移动候选确认属于 P2-02。

## 后果

- 监听只负责缩短发现变化的时间，最终状态仍由文件系统扫描决定；
- 重复、乱序和临时保存事件不会线性放大 UI 更新；
- 无法证明安全的增量事件会退化为单根扫描，不会扩大到全部磁盘或任意路径；
- 一致性扫描期间该根的卡片按批次重新出现，后续可在不改变协议的情况下加入暂存索引与原子视图交换；
- 当前自动恢复优先保证正确性，极端高频写入下的增量局部解析和资源调度属于 P2-06。

## 拒绝的方案

- 把平台事件序列保存为权威数据库或事务日志；
- 对 `rename-from` 与 `rename-to` 按到达时间猜测配对；
- 忽略队列溢出并继续相信不完整的增量状态；
- 对每个原始事件立即执行一次扫描；
- 允许前端向一致性扫描命令传递任意绝对路径；
- 自动移动孤立 Sidecar 或覆盖疑似移动目标。
