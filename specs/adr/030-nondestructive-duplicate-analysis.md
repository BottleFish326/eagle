# ADR-030：非破坏性重复素材分析

- 状态：Accepted
- 日期：2026-08-20
- 对应：P3-05、P3-A07、P3-A08
- 实施门禁：阶段 2 退出后

## 背景

重复素材分析需要在多个根和深层目录中找出内容完全相同的文件，但文件名、路径、Sidecar ID、Tag 或预览相似度都不能证明字节相同。阶段 2 已有 `sha256-sample-64k-v1` 快速指纹和 Sidecar 中可选的完整 SHA-256，不过这些值记录的是某次元数据编辑时的文件；若直接当作当前结论，可能在文件后续变化、同步替换或时间戳被保留时报告过期重复。

硬链接还会让两个路径指向同一物理文件。它们与两份独立字节副本在释放磁盘空间、修改传播和用户风险上完全不同。视觉相似则是近似候选，不具有自动删除或替换引用的安全性。

## 决策

1. 重复分析是用户显式启动的只读运行期任务。输入使用 ADR-029 的精确选择快照或明确根 scope；结果、哈希和候选组只保存在有界内存 session，不写入 Sidecar、素材根、应用配置、数据库或权威索引。
2. 精确内容管线固定为：文件大小预分组 → 当前文件的 `sha256-sample-64k-v1` 筛选 → 当前文件流式完整 SHA-256 → 按 `(size, sha256)` 分组。只有最后一层至少两个成员时才是 `exact-content`；文件名、扩展名、MIME、mtime、稳定 ID 和快速指纹都不能单独确认重复。
3. Sidecar 中已有的完整摘要只可用于显示“历史指纹”或优先调度，不能代替本次完整哈希。每次正式分析必须从已授权 canonical path 重新读取文件全部字节。
4. 每项在开始和结束时检查大小、mtime、读取错误及快速指纹；任一变化或取消使该项成为 `source-changed`/`cancelled`，其摘要不进入确认组。完整哈希流式读取并复用全局 Hash 许可、5 秒协作检查点和后台降级，不把整个文件加载到内存。
5. 若平台能取得稳定物理文件标识，同一标识的多个路径标为 `same-file-alias`，从独立 `exact-content` 副本数中分离；平台不提供时保持 `physical-identity-unknown`，不能猜测。符号链接继续只诊断不跟随。
6. 每个成员保留自己的路径、根、稳定 ID 和 Sidecar 摘要。内容相同不代表元数据可合并；重复稳定 ID 是独立一致性错误，不能由内容组自动修复。
7. 视觉相似属于第二条独立管线，只输出 `visual-candidate` 和算法版本/距离。它不能提升为 `exact-content`，不能跨损坏/codec 缺失素材伪造分数，也不能触发自动删除、Sidecar 合并或 Markdown 重写。
8. 结果按组节省空间估计降序、摘要升序，组内按平台规范化根 ID/相对路径确定性排序。节省估计只统计独立物理文件，不把硬链接别名重复计算。
9. 产品阶段 3 只提供查看、筛选、定位和复制报告信息。任何未来删除必须新增 ADR，使用系统废纸篓、重新验证当前版本、显式选择保留项并单独证明引用/Sidecar 行为；P3-05 不提供删除、合并、去重替换或自动移动。
10. 诊断日志只记录任务 ID、阶段、计数、字节数、耗时、取消和稳定错误种类。路径和摘要不进入支持日志；用户可在界面中主动查看当前运行期结果。

## 影响

- 同名不同内容永远不会因名称或快速指纹进入确认重复组。
- Sidecar 历史摘要不能造成过期确认，代价是正式分析需要重新读取候选文件全部字节。
- 硬链接与独立副本具有不同、可解释的空间语义。
- 分析结果删除即可由文件系统重建，不会形成第二份素材状态数据库。
- 视觉相似可以以后按算法版本迭代，不会污染“字节完全相同”的确定结论。

## 不采用

- 只按文件名、大小、扩展名或 mtime 判断重复；
- 以快速采样摘要作为最终确认；
- 无条件信任 Sidecar 中的历史完整摘要；
- 把硬链接的多个路径当作多份可释放空间；
- 把感知哈希接近称为内容重复；
- 扫描时自动删除、合并、移动素材或改写引用；
- 把完整哈希和结果组保存进数据库或不可解释缓存。
