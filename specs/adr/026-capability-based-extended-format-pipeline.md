# ADR-026：能力驱动的扩展格式管线

- 状态：Accepted
- 日期：2026-08-19
- 对应：P3-01、P3-A01、P3-A02
- 实施门禁：阶段 2 退出后

## 背景

当前扫描器只为 PNG、JPEG、GIF 和 WebP 建立素材记录，其他文件即使能够识别也会被过滤；缩略图服务只接受 `AssetKind::Image` 并使用单一 `image` 解码器。直接把更多扩展名塞进现有分支会把“文件是否是素材”“是否能提取属性”“本机是否能生成预览”错误地绑定在一起，并可能使缺少原生编解码器的一台机器看不到另一台机器已经管理的素材。

SVG、HEIC、视频和 PDF 还会引入 XML、复杂容器或原生解码器。它们的失败边界、资源约束和打包条件不同，不能共享一个无上限的进程内解码入口。

## 决策

1. 建立静态 `FormatRegistry`。每个正式格式声明稳定 ID、扩展名、MIME、素材种类、内容签名识别器、只读属性提供器、静态预览提供器和动态预览策略。
2. 文件识别、属性提取和预览是三个独立能力。只要格式已注册且文件可读，即使属性解析失败或本机没有编解码器，也必须建立通用素材记录并继续合并相邻 Sidecar。
3. 内容签名优先于扩展名。扩展名只作为签名不充分时的有界候选；内容与扩展名冲突时保留素材并产生明确诊断，不按扩展名调用不匹配的解码器。
4. 安全 Rust 解析器可以在进程内运行，但必须复用共享资源控制器、取消检查、协作期限、最大输入窗口和输出分配限制。涉及 C/C++、系统组件或复杂文档执行面的提供器放入固定的应用自带 worker，父进程传入已授权 canonical path、限制和请求 ID，并可在硬超时后终止 worker。
5. worker 不从 `PATH` 搜索任意 `ffmpeg`、`heif-dec`、`qlmanage` 或其他用户程序，不开启网络，不解析授权根之外的相对引用，不把源文件复制进专有目录。
6. 缺少可选提供器返回稳定的 `codec-unavailable`/`preview-unavailable` 能力结果，UI 显示文件类型卡片；这不是文件损坏。损坏、超限、超时和扫描期间源变化使用不同原因。
7. 扩展属性进入 `AssetRecord` 的可选 `media` 结构，保持文件系统派生、可删除和可重建；宽高继续兼容现有 `dimensions`，时长、页数、采样率、声道、帧数、颜色空间和编码名称均不得写入 Sidecar。
8. 所有静态预览统一输出受限 PNG 缓存，缓存键加入格式提供器 ID/版本。动态预览不写回素材；不支持时明确降级，不用静态缩略图成功冒充动态预览支持。
9. 实施按“注册与通用卡片 → SVG → AVIF/HEIC → MP4/MOV/WebM → MP3/WAV/FLAC → PDF”分片，每片都先加入正常、损坏、截断、伪装和超限夹具，再开放正式能力。

## 影响

- 扫描器不再以“当前有缩略图解码器”决定文件是否进入素材目录。
- 查询可从第一片开始按 image/video/audio/pdf 类型工作，随后逐步获得可选媒体属性。
- SVG 可采用静态、无脚本的纯 Rust 渲染；HEIC/AVIF、视频和 PDF 的原生依赖可以独立打包、禁用或升级，不污染文件识别和 Sidecar 语义。
- worker 生命周期、协议版本和提供器版本成为缓存失效及诊断导出的组成部分。
- 阶段 2 的正式稳定性长测和三平台路径门禁仍必须先通过；本 ADR 只完成 P3-01 的实施准备，不把阶段 3 标记为已开始。

## 不采用

- 只按扩展名把文件塞进图片解码器；
- 因本机缺少编解码器而从扫描结果中隐藏素材；
- 在主桌面进程中无隔离地加载所有原生媒体库；
- 自动调用用户 `PATH` 中版本和许可证未知的媒体工具；
- 把提取的媒体属性写入 Sidecar，或持久化一份权威格式数据库；
- 为生成预览而改名、转码或覆盖原素材。
