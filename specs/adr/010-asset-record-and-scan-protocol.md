# ADR-010：统一素材模型、字段优先级与增量扫描协议

- 状态：Accepted
- 日期：2026-08-14

## 背景

运行时素材对象需要合并文件系统、文件内容、原生图片元数据和相邻 sidecar。若字段来源与覆盖顺序不明确，手工编辑 sidecar 可能伪造路径、MIME 或尺寸，外部文件变化也可能被旧元数据遮蔽。一次性返回大型扫描结果还会阻塞首屏，且无法及时取消。

## 决策

1. `AssetRecord` 是桌面端、索引和后续预览管线共享的唯一运行时素材模型，但不是落盘真相源。
2. 根 ID、路径、相对路径、文件名、扩展名、MIME、类型、大小、创建/修改时间、只读状态和尺寸只来自当前文件系统或文件内容。
3. EXIF 只读提取方向、拍摄时间、相机、镜头、软件、作者与版权等选定字段；P1 不提取 GPS，也不向原文件回写任何原生元数据。
4. Sidecar 只提供稳定 ID、Tag、评分、收藏、备注和别名。即使未知扩展字段与文件字段同名，也不能覆盖文件派生值。
5. Sidecar 缺失时保留文件记录并使用用户元数据默认值；Sidecar 损坏时保留文件记录，并附加 `invalid-sidecar` 素材级问题。
6. 扩展名属于受支持图片但文件头损坏时，素材仍保留在结果中，并附加 `invalid-image-metadata`；单文件错误不得升级为整根扫描失败。
7. P1 正式识别 PNG、JPEG、GIF 和 WebP。尺寸探测只读取必要文件头，不解码完整像素。
8. 扫描按有界批次产生 `ScanBatch`，每批包含顺序号、素材、目录级问题和访问文件数；桌面端通过 Tauri Channel 有序传输。
9. 取消使用线程安全的协作式令牌，在目录项和批次边界检查。已经完整解析并发送的批次保持有效，最终状态明确标记为 `cancelled`。
10. 根目录忽略规则在扫描前编译；语法无效时明确失败，不静默忽略规则。

## 后果

- UI 可以增量展示素材并在每个素材旁呈现局部错误；
- 外部修改图片后，下一次扫描不会被 Sidecar 中的陈旧或伪造字段遮蔽；
- 取消不会撤回已经发送的批次，调用方必须按扫描 ID 管理本轮结果；
- 完整像素解码、动画帧处理和缩略图容错仍属于 P1-06；
- 文件事件驱动的精确增量重扫与结果协调属于 P2，不改变本 ADR 的批次协议。

## 拒绝的方案

- 允许 Sidecar 覆盖 MIME、尺寸或磁盘时间；
- 某个文件解析失败就中止整个素材根；
- 扫描完成后一次性向前端返回全部素材；
- 为了读取尺寸解码整张图片；
- 把扫描结果写入权威数据库；
- 默认收集并展示完整 GPS EXIF 信息。
