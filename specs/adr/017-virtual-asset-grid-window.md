# ADR-017：素材网格基础窗口化与阶段 1 规模门禁

- 状态：Accepted
- 日期：2026-08-14
- 最近复核：2026-08-15
- 局部调整：ADR-014 第 9 条及其大结果集 DOM 后果

## 背景

P1-A12 要求在 M 数据集上连续滚动和筛选 30 分钟。首次浏览器回归显示，扫描和查询均能稳定处理 10,000 项，但原 CSS 网格会把每次筛选的全部结果创建为 React 卡片。10 秒预热后的 20 秒测试中，四种查询计数都正确，事件循环延迟 P95 为 38 毫秒，但长任务累计占测试时长的 54.4%，无法通过阶段 1 资源门禁。

缩略图的 `IntersectionObserver` 只能推迟图像读取，不能减少 React 节点、观察器和筛选时的挂载/卸载成本。若把基础虚拟化继续推迟到 P3-07，阶段 1 MVP 在其声明的 M 规模下不可持续使用。

## 决策

1. 阶段 1 在素材网格引入按行窗口化。外层列表只提供可滚动总高度，内层绝对定位到当前起始行，只挂载视口及上下各三行 overscan 的卡片。
2. 列数、卡片高度、行距和窗口边界由一个纯函数统一计算。断点继续与现有响应式布局一致：窄屏两列，普通窗口按最小列宽自适应。
3. 过滤结果仍是完整的有序素材键集合；窗口化只改变展示节点，不修改查询语义、选择语义、Sidecar 数据或文件系统状态。
4. 每个已挂载列表项声明完整集合的 `aria-setsize` 和 `aria-posinset`。方向键、Home 与 End 按完整结果集合计算目标；目标不在当前窗口时先滚动到对应行，再恢复焦点。
5. 缩略图继续按视口请求并在卡片卸载时释放对象 URL。窗口化不得预生成全量缩略图，也不得增加素材快照或持久数据库。
6. Obsidian 引用只为当前网格窗口及唯一选中的检查器素材解析。多选不触发额外解析；完整查询结果不能驱动全量引用对象生成。
7. M 稳定性验收的自动判定增加卡片节点上限 120。测试使用 10,000 素材，60 秒预热，随后每秒滚动、每 8 秒轮换典型查询并每 5 秒采集 JavaScript 堆、DOM、卡片数和事件循环延迟。
8. P3-07 仍负责多种缩略图尺寸、动态缩放、排序、快速/全屏预览、命令面板、完整可访问性审计以及更大规模和不同窗口形态的生产优化，不重复要求“首次引入基础窗口化”。

## 后果

- M 数据集的 React 卡片和 DOM 数量不再随筛选结果线性增长；
- 筛选仍可返回完整 10,000 项，列表滚动高度保持与全量布局一致；
- 卡片跨窗口卸载会释放缩略图对象 URL，重新进入窗口时可从派生缓存读取；
- Obsidian 引用解析工作量随窗口大小变化，而不随完整筛选结果数量增长；
- 行高计算依赖当前固定的 4:3 预览和单行标题布局，P3-07 引入可变尺寸前必须扩展测量模型；
- 虚拟化属于纯展示优化，不改变 ADR-001 的文件系统真相源，也不产生可持久化素材状态。

## 拒绝的方案

- 只保留缩略图懒加载但继续挂载全部卡片；
- 通过 Canvas 绘制整个网格并放弃原生按钮、拖放和可访问语义；
- 把查询截断为当前视口数量；
- 为改善渲染而把素材快照保存到 IndexedDB 或其他数据库；
- 口头放宽 P1-A12 的长任务或资源曲线门槛。
