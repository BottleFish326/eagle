# ADR-021：显式元数据合并与同步冲突副本诊断

- 状态：Accepted
- 日期：2026-08-19
- 关联：ADR-001、ADR-002、ADR-007、ADR-011、ADR-018、ADR-020
- 部分替代：ADR-011 的摘要单值并发版本规则

## 背景

ADR-011 用 Sidecar 内容摘要阻止静默覆盖，但摘要本身不能表达“文件被同步工具替换后内容恰好相同”这一外部版本事件，也没有规定冲突后的字段级选择。P2-04 还必须处理 Dropbox、Syncthing 等工具在素材根中留下的冲突副本。这些副本是用户文件，自动删除、按文件名猜测原件或自动拼接备注都会破坏文件系统真相源边界。

## 决策

1. 桌面端扫描每个有效 Sidecar 时记录 `{modifiedUnixMs, size, digest}` 完整版本。单项和批量元数据编辑都携带调用方观察到的三元版本；任一分量不同即视为过期。首次 Sidecar 编辑仍用“期望不存在”，兼容核心 API 可继续接受旧摘要，但正式桌面链路使用完整版本。
2. Sidecar 读取在读文件前后比较大小与毫秒级修改时间，并核对实际读取字节数；读期间发生可观察变化时返回冲突。写入前及原子替换前继续重复版本校验。SHA-256 负责内容身份，大小用于快速异常检测，mtime 负责识别同内容替换；三者缺一不作为正式桌面写入的完整观察版本。
3. 乐观写入失败后，后端重新读取当前有效 Sidecar，以目录记录作为 `base`、外部文件作为 `current`、用户补丁作用于 `base` 的结果作为 `proposed`，生成 UUIDv7 不透明冲突计划。计划只保存在有界运行期内存中，不持久化用户字段副本；最多保留 256 项。
4. 只有用户补丁触及、外部也改变且双方结果不同的字段属于重叠冲突。界面必须展示外部修改时间、外部变化字段，以及 `base/current/proposed` 三个值。稳定 ID 外部变化需要警告，解决时保留当前磁盘 ID。
5. Tag 是集合字段。重叠时用户必须明确选择“合并 Tag”“保留外部”或“使用我的”。“合并”把用户相对 `base` 的增加/删除意图应用到 `current`；非重叠 Tag 补丁可以在用户确认解决后安全重放。
6. 评分、收藏、备注和别名按标量/整值字段处理。重叠时每个字段必须明确选择“保留外部”或“使用我的”；禁止自动串接备注或猜测胜出版本。未被补丁触及的字段及未知 Sidecar 字段始终保留当前外部值。
7. 解决命令只接收不透明冲突 ID 与字段选择。写入前重新检查授权根、扫描互斥、素材/Sidecar 路径边界及捕获后的完整 Sidecar 版本；再次变化时拒绝并要求重新扫描。成功持久化后才更新运行期目录。放弃冲突只移除运行期计划并重扫，不写或删除 Sidecar。
8. 一致性诊断只在文件名含 `.asset` 的 YAML/YML 中识别已知模式：Syncthing `.sync-conflict-`、Dropbox `conflicted copy (...)`，以及保守的通用 `conflict copy (...)`、`.conflicted.`、`-conflicted-copy`。只有冲突副本能解析且恰好存在一个相同稳定 ID 的普通 Sidecar 时才显示字段差异；没有或存在多个原件时显示不确定原因，不猜测。
9. 同步冲突副本只进入诊断视图，显示来源、mtime、可确定的原文件和 Tag/评分/收藏/备注/别名差异。应用不自动删除、移动、重命名、覆盖或合并冲突副本；损坏副本也保持原样。
10. 解决与放弃操作写入不含路径和用户字段的结构化诊断事件。同步冲突诊断本身不创建第二份持久状态。

## 后果

- 同内容但 mtime 改变、同大小但内容改变和普通内容变更都会阻止旧视图覆盖磁盘；
- 用户可以保留外部 Tag 同时应用自己的集合增量，而备注等字段不会被静默拼接；
- 冲突计划随应用退出丢失，重启后通过重新扫描和再次编辑重新建立，避免应用私有状态成为恢复依赖；
- 已知同步命名模式可能漏报厂商新格式，但保守识别避免把普通 Sidecar 误当冲突副本；
- mtime 使用文件系统提供的毫秒观察值，不作为内容证明，最终仍由 SHA-256 参与完整版本比较；
- P2-03 事务恢复日志仍以原/计划/当前内容摘要证明可恢复状态；事务的新编辑入口使用完整三元观察版本，两者职责不同。

## 拒绝的方案

- 继续只用 SHA-256 作为桌面编辑观察版本；
- 冲突时默认“最后写入者获胜”；
- 自动对所有字段执行三方文本合并；
- 把冲突计划、目录基线或同步副本索引写入数据库；
- 根据相似文件名把冲突副本自动改名为原件；
- 在发现 Dropbox 或 Syncthing 冲突副本时自动删除其中任意一份；
- 原件不唯一时按路径距离或修改时间猜测对应关系。
