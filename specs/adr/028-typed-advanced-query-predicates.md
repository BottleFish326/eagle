# ADR-028：定型高级查询谓词与独立结果预言机

- 状态：Accepted
- 日期：2026-08-20
- 对应：P3-02、P3-A03
- 实施门禁：阶段 2 退出后

## 背景

阶段 1 查询语言已经支持 Tag、类型、扩展名和收藏，但 P3-02 还需要按尺寸、宽高比、日期、时长、页数、颜色空间、评分、路径和根目录过滤。若把这些值都当作字符串比较，会产生 `10 MiB < 2 MiB`、本地时区漂移和浮点宽高比边界等错误；若所有条件都预先建立倒排表，则高基数字段会使可重建索引的内存无界增长。

P3-A03 还要求查询结果与离线验证程序一致。让验证程序调用产品的解析器或索引只能证明同一实现与自身一致，不能发现语法解析、缺失值或边界比较的共同错误。

## 决策

1. 查询语言版本 2 是版本 1 的向后兼容扩展。现有裸 Tag、`tag:`、`any:`、`type:`、`ext:` 和 `favorite:` 的语义不变；未知字段继续是可定位的解析错误，不能退化为零结果。
2. 高级字段先解析成定型 AST，再执行。字节、像素、时长、页数和评分使用整数；宽高比使用约分后的正整数分数并以交叉乘法比较；时间必须是带 `Z` 或显式偏移的 RFC 3339 时间并转换为 Unix 毫秒。查询执行不使用二进制浮点数比较边界。
3. 数值字段支持 `=`, `<`, `<=`, `>`, `>=`。省略比较符等价于 `=`；同一字段的多个范围条件取交集，空交集在解析阶段报告 `conflicting-range`，不以合法零结果掩盖输入错误。
4. 可为空的文件派生字段在普通比较时不匹配。只有该字段显式接受 `unknown` 时才匹配缺失值；`unknown` 与同字段的数值范围同时出现属于冲突。缺少 codec 或属性提供器不能被错误解释为数值 0。
5. `width`、`height`、`aspect` 和 `orientation` 使用面向显示的有效尺寸：JPEG EXIF 方向 5–8 以及视频旋转元数据会交换原始宽高。该计算是可重建的查询派生值，不写入 Sidecar。
6. 类别字段同一次或重复出现的值合并为 OR；不同字段之间以及多个路径片段之间使用 AND。Tag OR 仍只使用现有 `any:(...)`，P3 不引入任意嵌套布尔表达式。
7. `path:` 匹配以 `/` 表示分隔符、NFC 规范化的根内相对路径连续子串，跨平台均区分大小写。`root:` 只接受稳定根 UUID，不接受显示名或绝对路径。该定义避免保存过滤器因平台路径折叠规则而静默改变含义。
8. 索引采用混合执行：Tag、类型、扩展名、收藏、根和低基数类别使用集合索引；范围和路径谓词先利用已选集合缩小候选，再对 `AssetRecord` 线性求值。只有 L 数据集证据表明超过 100 ms p95 时，才把对应整数值加入可重建排序索引，并记录内存增量。
9. P3-A03 使用受 Schema 约束的查询一致性语料。每个合法用例同时保存文本表达式、与产品 AST 无关的规范化 oracle 谓词以及固定期望键；离线验证器独立计算 oracle 结果、核对固定期望，再与产品结果比较。验证器不得依赖 `asset-index`、目录查询命令或桌面适配器。
10. 查询、oracle、索引和保存过滤器都不保存源素材副本或查询结果快照。诊断只记录字段、错误种类、候选数和耗时，不记录路径、Tag 或查询原文。

## 影响

- 高级查询的单位、时间、缺失值和边界比较具有唯一语义，可由文本栏、可视化编辑器和保存过滤器共享。
- codec 不同或属性提取失败的机器不会把未知值误当作零值，从而减少跨平台过滤漂移。
- 混合索引避免为文件大小、时间和任意路径字符串建立无界映射，同时保留按证据优化的空间。
- P3-A03 能发现解析器、执行器和索引共同产生的结果错误，而不是只做实现内自检。

## 不采用

- 以字符串或 JavaScript `Number` 比较全部高级字段；
- 允许无时区日期按当前机器本地时间解释；
- 把缺失媒体属性填成 `0`、空字符串或 `false`；
- 默认提供任意嵌套 AND/OR/NOT 表达式；
- 按根显示名或绝对路径持久化过滤条件；
- 让离线验证程序复用产品解析器、索引或 Tauri 命令；
- 为查询性能保存不可重建的素材结果表或数据库索引。
