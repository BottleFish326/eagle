# ADR-002：Sidecar 格式、稳定 ID 与写入规则

- 状态：Accepted
- 日期：2026-08-14

## 背景

原始素材不能因打标而被修改，同时元数据需要可读、可同步、可版本管理并随素材移动。

## 决策

1. `name.ext` 的元数据文件命名为 `name.ext.asset.yml`。
2. Sidecar 使用 UTF-8 YAML；其逻辑结构由 JSON Schema 描述。
3. 稳定 ID 使用 UUIDv7。首次产生用户元数据或外部稳定引用时创建 sidecar 和 ID。
4. `schema` 为整数版本；当前版本为 `1`。
5. 序列化固定字段顺序，使用 LF 和文件末尾单一换行。
6. 读取时保留未知字段，向前兼容；解析失败时不得覆盖原文件。
7. 写入流程为：读取当前摘要、同目录创建临时文件、完整写入、刷新、原子替换。
8. 写入前若摘要变化，返回冲突；Tag 可在用户确认后做集合合并，备注等字段不得静默合并。
9. 修改 sidecar 前后必须验证原始素材没有被打开为可写模式。

最小结构：

```yaml
schema: 1
id: "0198a7c2-8341-7a31-b842-f15d39f33c18"
tags:
  - ui/icon
rating: 4
favorite: true
updatedAt: "2026-08-14T12:30:00+08:00"
```

## 后果

- 文件管理器中会出现相邻 sidecar，可通过忽略规则隐藏；
- 用户应同时移动素材和 sidecar；
- 手工编辑具有可操作性，但应用必须处理格式错误和并发冲突；
- UUIDv7 具有时间有序性，但产品语义只依赖全局唯一性。

## 拒绝的方案

- 把 Tag 写回 EXIF/XMP；
- 以绝对路径作为素材 ID；
- 将所有素材元数据集中到一个大 JSON/YAML 文件；
- 使用仅应用可读的二进制格式。
