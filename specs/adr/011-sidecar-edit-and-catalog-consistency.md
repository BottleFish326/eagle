# ADR-011：Sidecar 编辑、并发控制与目录一致性

- 状态：Accepted
- 日期：2026-08-14
- 部分替代：ADR-021 以 mtime、大小与 SHA-256 完整版本替代正式桌面链路的摘要单值规则

## 背景

P1-04 需要在不修改原始素材、也不引入权威数据库的前提下编辑 Tag、评分、收藏、备注和别名。编辑同时涉及磁盘上的 Sidecar 和运行时内存索引；若写入版本、失败边界或更新顺序不明确，可能静默覆盖用户的外部修改，或让界面展示磁盘上并不存在的状态。

## 决策

1. 首次编辑时才创建相邻 Sidecar，并生成 UUIDv7 稳定 ID；后续编辑保留该 ID。
2. 每个编辑目标必须携带调用方最后观察到的 Sidecar 内容摘要。`null` 表示调用方观察到 Sidecar 缺失，字符串表示精确的 SHA-256；两者都不是“忽略版本”。
3. 写入前和原子替换前各检查一次期望版本。版本不一致时返回冲突，保留磁盘现状，不自动覆盖或合并。
4. `setTags` 表示完整替换 Tag 集合；`addTags` 与 `removeTags` 表示集合增量。同一补丁不能把 `setTags` 与增删操作混用，也不能同时添加和移除同一 Tag。
5. 评分、收藏、备注和别名使用显式字段补丁；缺失字段表示“不修改”。空补丁和超出字段约束的补丁在写盘前拒绝。
6. 编辑现有 Sidecar 时保留所有未知字段，继续采用确定性 YAML 序列化、同目录临时文件、文件同步和原子替换。
7. 批量操作以单个素材为隔离边界，返回成功记录和逐项失败。一个目标失败不阻止其他目标完成，也不回滚已成功目标。
8. 只有 Sidecar 成功持久化后，才用新的 `AssetRecord` 更新内存目录和倒排索引；失败目标保留原索引状态。前端使用返回记录替换对应视图项。
9. P1 不持久化内存目录。应用重启后通过扫描 Sidecar 重建相同状态。

## 后果

- 外部编辑或同步工具改变 Sidecar 后，旧界面发起的写入会得到明确冲突，不会静默丢失外部内容；
- 批量编辑可以部分成功，调用方必须展示逐项失败并允许用户在重新扫描后重试；
- Tag 修改无需等待重新扫描即可参与查询；
- 原始素材从未以写模式打开，所有用户元数据仍可完全从文件系统恢复；
- 带持久化事务日志的批量继续、回滚和崩溃恢复属于 P2-03，不在 P1-04 范围内。

## 拒绝的方案

- 用内存状态直接覆盖 Sidecar，不检查磁盘版本；
- Sidecar 写入失败后仍先更新索引，以“稍后同步”掩盖错误；
- 把 Tag 或稳定 ID 只存入不可审计的数据库或应用私有缓存；
- 首次扫描就为所有无元数据素材批量创建 Sidecar；
- P1 批量编辑采用全有或全无语义，但没有可靠事务日志支撑。
