# ADR-024：有界、脱敏的支持诊断

- 状态：Accepted
- 日期：2026-08-19
- 对应：P2-07

## 背景

P1-09 的诊断服务只在进程内保留最近 256 条事件并支持手动导出，无法覆盖重启或崩溃前线索。支持人员还需要判断运行期目录是否与当前磁盘收敛，并解释某个稳定素材 ID 来自哪个 Sidecar，但这些能力不能建立第二份素材数据库，也不能把用户绝对路径和元数据正文写入可分享日志。

## 决策

1. 运行事件同时进入最多 256 条的内存环形缓冲和固定日志目录中的 JSON Lines 文件；事件具有 `info`、`warning`、`error` 等级以及稳定的 category/code。
2. 单个运行日志最多 1 MiB，当前文件与历史分段合计最多保留 5 个。轮换只处理固定名称的普通文件；符号链接或非普通条目使写入安全失败。
3. category、code、明细数量和明细长度均有硬上限。绝对路径、用户目录形式和 Windows 路径值在落盘前替换为 16 位 SHA-256 指纹，不记录查询、Tag、备注、别名或 Sidecar 正文。
4. 诊断导出 Schema 2 在既有构建、平台、配置、缓存、目录访问状态上增加 warning/error 聚合、滚动日志占用，以及扫描、监听、调度和缓存性能快照。
5. 库一致性检查只快照运行期目录并读取文件类型、存在性、Sidecar 邻接关系、稳定 ID 重复和已隔离解析问题。最多返回 512 条明细，额外问题只计数并标记截断。
6. 素材追踪命令只接受稳定 UUID，不接受路径。它从运行期目录定位记录，逐步报告根关联、素材文件、相邻 Sidecar 解析、ID 匹配和解析问题；输出只含相对路径与短路径指纹。
7. 一致性检查和素材追踪不得写入素材、Sidecar、配置、缓存或诊断快照，也不保存素材列表。文件系统和相邻 Sidecar 仍是唯一真相源。

## 影响

- 支持日志具有跨重启线索且磁盘占用严格受限；高等级事件会请求数据同步，普通事件只刷新文件缓冲。
- 一致性报告是时间点只读观察；活动扫描或尚未完成权威扫描时明确返回 `authoritative: false`，不能把报告当作持久化索引。
- 运行日志位于应用日志目录的 `diagnostics/runtime`，诊断导出仍使用独立原子 JSON 文件，二者均可删除并重新生成。
- 按 ID 查不到记录时不会扫描任意路径；用户应先完成已授权根的完整扫描。

## 不采用

- 把运行事件、素材快照或追踪结果写入 SQLite、IndexedDB 或搜索数据库；
- 在日志中保存绝对路径后依赖分享前人工清理；
- 接受前端传入任意路径进行支持扫描；
- 一致性工具自动修复、移动、删除或重写素材与 Sidecar。
