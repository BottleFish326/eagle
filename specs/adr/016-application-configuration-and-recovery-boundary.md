# ADR-016：应用配置、诊断与恢复边界

- 状态：Accepted
- 日期：2026-08-14

## 背景

P1-09 需要保存查询、Tag 三态和当前 Vault，提供缓存重建与最小诊断导出，同时继续满足“文件系统与 Sidecar 是唯一素材真相源”。如果 UI 使用 LocalStorage 或数据库保存素材记录，或恢复入口可以接收任意删除路径，就会产生第二真相源或越过应用数据边界。诊断文件如果包含绝对路径、查询文本、Tag 或备注，也会泄露用户素材信息。

## 决策

1. 应用偏好保存为操作系统应用配置目录中的普通 YAML 文件 `application.yml`，结构由 `schemas/application-config.schema.json` 约束，当前 Schema 版本为 1。
2. P1 只保存查询文本、Tag 的 `include`/`exclude` 状态和当前 Vault UUID。素材记录、选择、查询结果、缩略图键和扫描快照不进入应用配置。
3. 配置更新先验证长度与数量边界，再写入同目录临时文件、同步文件、原子替换并同步父目录；失败时不提交新的内存状态。未知顶层字段和 `ui` 字段在更新后保留。
4. 缩略图缓存根为应用缓存目录下固定的 `thumbnails-v1`。固定标记内容同时声明缓存归属与布局版本。启动时若目录非空但标记缺失，或标记版本不兼容，只重置这个固定目录并记录移除数量；符号链接、非目录根和异常标记仍作为不安全状态拒绝。
5. “清理缓存并重建”命令不接受路径参数。它在固定缓存边界持有排他锁，验证规范父目录、目录名与标记后重置缩略图缓存，并清空运行期目录和倒排索引。前端仅在没有活动扫描时允许二次确认，完成后重新扫描所有启用且可访问的素材根。
6. 重建不删除或修改素材、相邻 Sidecar、`application.yml`、`library-roots.yml` 或 `obsidian-vaults.yml`。配置属于用户状态；内存目录、索引和缩略图属于派生状态。
7. 诊断服务在内存保留最近 256 条结构化事件。导出使用原子写入生成 JSON 快照，包含构建、操作系统、架构、配置计数、缓存统计、目录计数、访问状态和最近事件。
8. 诊断文件不包含素材或 Vault 绝对路径、文件名、查询文本、Tag、备注或 Sidecar 内容。已授权路径只输出 16 位 SHA-256 指纹和匿名序号，用于比较同一次支持会话中的路径是否相同。
9. 设置页展示实际配置、缓存和日志目录，用户可据此备份配置或独立删除派生数据。诊断导出只写入应用日志目录下的 `diagnostics`，不写入素材根或 Vault。

## 后果

- 应用重启后可恢复用户视图，但素材状态仍完全由原文件与 Sidecar 重建；
- 删除缓存、缓存版本升级或内存索引丢失不会造成 Tag、评分、收藏、备注和稳定 ID 丢失；
- 配置文件可手工审阅和备份，并保留未来字段；
- 最小诊断足以识别构建、缓存迁移、访问状态和近期操作类别，同时不暴露素材内容；
- P2 仍需增加崩溃日志、容量回收、配置迁移与外部配置变更处理。

## 拒绝的方案

- 使用 SQLite、IndexedDB 或 LocalStorage 保存素材记录或过滤结果；
- 在素材根目录写入应用配置、索引或诊断文件；
- 让前端向清理命令传入任意目录；
- 缓存版本不兼容时继续读取旧条目；
- 在诊断包中输出绝对路径、文件名、Tag、备注、查询原文或 Sidecar 正文；
- 清理缓存时顺带删除应用配置或素材 Sidecar。
