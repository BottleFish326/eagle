# ADR-019：稳定身份扫描收敛与显式 Sidecar 重新关联

- 状态：Accepted
- 日期：2026-08-19
- 关联：ADR-001、ADR-002、ADR-004、ADR-010、ADR-018
- 替代：ADR-004 第 6 项在单文件重新关联中的执行机制；ADR-018 第 7 项“扫描开始时清除根目录运行期记录”的实现方式

## 背景

P2-01 在完整扫描开始时清除目标根的运行期记录，能够保证删除事件最终收敛，但成对移动素材与 Sidecar 时，前端会先失去旧键对应的选择状态。只移动素材或只移动 Sidecar 时，应用还需要在不猜测、不静默改盘的前提下生成可验证候选。

文件大小只能排除明显不匹配，采样指纹可以低成本缩小范围，最终身份确认仍需要完整 SHA-256。相同内容可以有多个合法副本，因此即使哈希完全相同也不能代表用户意图。

## 决策

1. 首次创建或后续编辑 Sidecar 时，写入素材字节数、`sha256-sample-64k-v1` 快速指纹和完整 SHA-256。该字段仍属于 Sidecar Schema 1 的可选向后兼容字段；应用不为旧 Sidecar 静默补写。
2. 完整扫描保留该根的旧运行期记录，同时按批次暂时 upsert 新记录；扫描成功后一次性以完整结果替换该根。扫描取消或失败时恢复扫描前快照，并向前端发送需要删除和恢复的运行期记录。
3. 扫描前后都只有一个相同稳定 ID 时，生成旧键到新键的移动映射。前端使用映射迁移选择与选择锚点；重复 ID 不生成映射。
4. 素材与相邻 Sidecar 成对移动时，Sidecar ID、Tag 和其他用户元数据随新路径重新解释，不创建第二份素材记录。
5. 孤立诊断只扫描已配置且可访问的素材根。相邻素材缺失的 `.asset.yml` 标记为 `orphan-sidecar`，其原相邻路径标记为丢失素材。
6. 候选依次通过字节数、快速指纹和完整 SHA-256。缺少持久化指纹的旧 Sidecar 只显示诊断，不根据文件名或大小生成猜测候选。
7. 诊断本身只读。候选以运行期不透明 ID 保存在桌面后端；前端确认时只提交候选 ID，不提交任意文件路径。
8. 确认操作重新校验授权根、Sidecar 摘要与稳定 ID、素材大小、快速指纹、完整 SHA-256，并确认目标 Sidecar 不存在。随后使用“目标硬链接创建成功后再移除源文件”的无覆盖操作；任一步失败都不得覆盖或删除目标。
9. 单候选仍需用户确认；多候选全部标记为歧义，由用户明确选择其中一个或保持未解决。确认成功后重新扫描该根。
10. 所有目录、候选与移动映射都只存在于内存，可由文件系统和 Sidecar 重建；不新增数据库或权威身份表。

## 后果

- 成对移动时，卡片在扫描期间保持可见，扫描完成后选择可以迁移到新路径；
- 只移动一侧时，应用能够显示孤立 Sidecar、丢失素材和待确认移动，但不会因扫描本身修改任何文件；
- 旧 Sidecar 没有指纹时不会产生不可靠候选，用户需在素材仍相邻时通过一次正常元数据编辑建立指纹；
- 硬链接与删除之间进程终止可能留下两份完整 Sidecar，后续扫描会显式显示冲突；不会出现半文件或目标覆盖；
- 跨文件系统或不支持硬链接的目标会安全失败，未来可由 P2-03 文件事务日志提供可恢复的复制/删除流程；
- 扫描期间查询可能短暂同时包含旧键与新键，完成事件负责确定性删除旧键。

## 拒绝的方案

- 根据文件名、路径相似度、mtime 或单独的文件大小自动关联；
- 唯一 SHA-256 候选无需用户确认；
- 让前端向确认命令发送源路径和目标路径；
- 在 Unix 上直接使用可能覆盖目标的 `rename`；
- 为移动身份建立 SQLite、IndexedDB 或其他权威数据库；
- 扫描时自动删除孤立 Sidecar、重复 Sidecar 或内容相同的素材。
