# ADR-027：用户级保存过滤器与显式 Tag 重命名

- 状态：Accepted
- 日期：2026-08-19
- 对应：P3-03、P3-A04、P3-A05
- 实施门禁：阶段 2 退出后

## 背景

保存过滤器需要跨重启恢复、可读、可备份和可同步，但不能保存具体素材列表或成为查询结果数据库。应用允许同时启用多个素材根，因此把过滤器写进任意一个素材根会产生所有权歧义、额外修改用户素材目录，并且无法自然表达跨根查询。把过滤器混入 `application.yml` 又会让高频 UI 偏好和可独立同步的命名查询共享同一个冲突面。

Tag 重命名还会影响查询文本。若应用直接做字符串替换，可能误改备注、字段值或同名前缀；若静默忽略，则保存过滤器会在用户以为重命名完成后产生不同结果。

## 决策

1. 保存过滤器属于当前操作系统用户的应用配置，而不是素材库内容。文件固定为应用配置目录中的 `saved-filters.yml`，与 `application.yml`、`library-roots.yml` 并列，不写入素材根、Vault、Sidecar、缓存或数据库。
2. 文件逻辑结构由 [`saved-filters.schema.json`](../../schemas/saved-filters.schema.json) 约束，Schema 版本从 1 开始。顶层最多 512 个过滤器；每项使用 UUIDv7 稳定 ID、1–128 字符显示名、最长 4,096 字符的单行查询、显式作用域、排序字段/方向及创建/更新时间。
3. 作用域只能是“所有已启用根”或一组明确的根 UUID。保存根 ID 而不保存绝对路径；根被停用、移除或离线时保留过滤器并显示作用域诊断，不擅自删除或改成全部根。
4. 过滤器只保存查询表达式，不保存匹配素材 ID、路径、计数、缩略图、解析 AST 或索引快照。每次使用都由当前文件系统扫描结果和当前查询解析器重新求值；删除所有缓存后结果必须可恢复。
5. 排序只保存稳定枚举字段和方向。未知或当前版本不支持的字段使该过滤器进入可修复的无效状态，不能损坏整个文件或退回某个隐式默认值。
6. 更新采用文件级完整版本（mtime、大小、SHA-256）乐观并发控制和同目录临时文件原子替换。加载和写回保留未知顶层及条目字段；外部同步修改时不静默覆盖或自动合并。
7. 过滤器 ID 必须唯一；显示名按 Unicode 原文展示，但去除首尾空白后的大小写折叠名称不得重复。重复、无效查询或未知根只隔离对应条目，其余合法条目仍可读取。
8. Tag 重命名先完整解析每个查询，并只按查询 AST 中的精确 Tag 节点计算影响。应用展示受影响过滤器和重写前后文本，让用户选择更新所选项、保留原表达式或取消；解析失败的表达式永不自动改写。
9. Tag 与过滤器修改是同一用户动作的两个可验证文件计划，但不是跨文件系统的伪原子事务。执行前记录每个 Sidecar 与过滤器文件版本，沿用阶段 2 事务检查点；任一外部变化都停止未执行项并给出继续/恢复清单。
10. 删除或重命名过滤器只改变 `saved-filters.yml`，不修改素材、Sidecar、缓存或 Markdown。诊断导出只报告过滤器数量和错误种类，不输出名称、查询或 Tag 原文。

## 影响

- 多根查询拥有唯一明确的用户级归属，不需要在素材目录增加隐藏配置文件。
- 用户可单独备份或同步保存过滤器；同步冲突仍以普通文件冲突显式处理。
- 删除应用缓存不会丢失保存项，也不会因为保存项恢复出陈旧素材快照。
- Tag 重命名可以准确提示影响并由用户控制，不以字符串替换破坏查询语义。
- P3-03 实现需要独立配置管理器、查询引用分析和事务适配，但可以复用现有原子写入、版本检查和恢复机制。

## 不采用

- 每个素材根各写一份过滤器文件；
- 把保存过滤器放进缩略图或扫描缓存；
- 使用 SQLite、IndexedDB 或 LocalStorage 保存过滤器或匹配结果；
- 保存具体素材 ID/路径列表来加速恢复；
- Tag 重命名时对查询文本做全局字符串替换；
- 外部文件变化后以“最后写入者获胜”静默覆盖。
