# ADR-014：桌面 UI 状态与 API 边界

- 状态：Accepted
- 日期：2026-08-14

## 背景

P1-07 需要把素材根目录、增量扫描、内存查询、Sidecar 编辑和缩略图管线组合为可操作桌面界面，同时继续遵守“不使用权威数据库”和“删除派生状态后可恢复”的产品不变量。若 React 视图自行持久化素材记录、重新实现查询语义或直接读取任意文件路径，会产生第二真相源并绕过已验收的 Rust 边界。

## 决策

1. React 只在当前进程维护瞬态视图状态，包括扫描批次合并后的 `Map<assetKey, AssetRecord>`、当前选择、查询文本、Tag 三态和可见键，不写入 IndexedDB、LocalStorage 或其他素材数据库。
2. 前端通过 `DesktopApi` 接口调用桌面能力。正式运行时适配到 Tauri 命令；非 Tauri 的 Vite 开发预览适配到内存演示实现。演示实现不得读取或写入用户文件，也不得进入正式 Tauri 数据路径。
3. 素材根启动扫描后，前端按 Channel 批次 upsert `AssetRecord`。移除或停用素材根时只从瞬态 Map 移除对应 `rootId` 的记录；磁盘操作继续由既有根目录命令约束。
4. 前端不解释正式查询语法。搜索文本与 Tag 三态被组合为表达式后提交给 Rust 查询引擎，结果只用键映射回前端 Map；结构化解析错误必须显示在搜索栏附近。
5. Tag 三态固定为 neutral → include → exclude → neutral。包含与排除均生成显式 `tag:"..."` 或 `-tag:"..."` 词，以保持空格、冒号和转义规则与正式解析器一致。
6. 缩略图组件使用 `IntersectionObserver`，只在卡片进入视口预取边界后调用 P1-06 协议。对象 URL 在组件卸载或素材变化时释放；损坏素材显示占位原因。
7. 单击选择一项，Ctrl/Command 切换选择，Shift 选择可见范围；全选只作用于当前查询结果。所有 Sidecar 编辑都携带每项当前摘要并消费逐项失败结果。
8. 网格使用原生按钮和可访问名称，支持方向键、Home、End、Enter/Space；`/` 聚焦搜索，Escape 关闭弹窗或清除选择。状态与错误使用 `aria-live`、`status` 或 `alert`，不只依赖颜色表达。
9. P1-07 采用响应式三栏布局：左侧过滤、中央扁平网格、右侧检查器。窄窗口下检查器转为浮层，快速过滤保持可用；生产级虚拟化与缩略图尺寸控制仍属于 P3-07。

## 后果

- UI 重启后必须重新扫描文件和 Sidecar，不会从隐藏数据库恢复素材状态；
- 正式运行和浏览器开发预览共享相同组件与类型，但只有正式适配器能产生文件系统副作用；
- 查询、Sidecar 并发控制、缓存边界继续只有一套 Rust 语义；
- 素材数量很大时，当前 CSS 网格仍会保留全部匹配卡片节点，P3-07 必须引入生产级虚拟化；
- P1-09 需要决定哪些纯应用偏好可写入可读配置，但不得持久化素材记录或选择状态。

## 拒绝的方案

- 用 IndexedDB 保存素材记录、Tag 或查询索引；
- 在 TypeScript 中复制一套正式查询解析器；
- 让 WebView 直接通过任意绝对路径读取缩略图；
- 扫描时为全部素材创建对象 URL；
- 把浏览器演示数据或画布缩略图用于 Tauri 正式运行；
- 批量编辑失败后仍乐观地把全部选中项显示为成功。
