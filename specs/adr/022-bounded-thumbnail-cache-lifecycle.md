# ADR-022：有界缩略图缓存生命周期与中断安全清理

- 状态：Accepted
- 日期：2026-08-19

## 背景

P1-06 的缩略图缓存已经满足按需生成、版本化键、固定清理边界和损坏隔离，但没有容量、保留期限、孤立项回收及真实进程中断恢复。只依赖键中包含解码器版本会阻止旧条目命中，却不能识别并回收它们；直接递归清空当前缓存根还会在中断时留下缺失或半清理目录。

缓存必须继续只是普通派生文件，不能引入 SQLite、隐藏数据库或用户元数据清单。

## 决策

1. `thumbnails-v1` 保持唯一固定缓存根，布局标记升级为 v2。每个缩略图由同分片中的 `<key>.png` 和 `<key>.json` 组成；JSON 只保存 Schema、缓存键、不可逆源令牌、解码器版本和请求长边，不保存路径、Tag、备注或其他用户字段。
2. 默认策略为最多 20,000 个条目、PNG 与描述文件合计最多 1 GiB、最后使用后保留 30 天。有效命中更新 PNG 的 mtime，作为不影响源文件的 LRU 时间。
3. 缓存维护依次移除不完整/损坏项、旧解码器项、不属于当前内存目录的孤立项、过期项，再按 LRU 回收到容量以内。容量估计超过限制时立即维护；正常写入按 1–64 次的有界间隔维护。
4. 应用启动时执行格式、损坏、过期和容量维护；所有并行素材扫描结束后使用完整内存目录快照回收孤立项；设置页允许用户显式执行同一维护。没有启用扫描快照，因此不存在需要保留的权威扫描状态。
5. 解码器版本同时参与缓存键和条目描述。升级后只移除描述为旧解码器的条目；当前版本的其他有效条目可以保留。布局本身不兼容时仍按 ADR-003 整版重建。
6. PNG 与描述文件分别使用同目录临时文件、文件同步和原子持久化；只有两者都存在且描述匹配时才命中。不完整文件在启动或维护时回收。
7. 全量清理不原地递归删除活动根。操作先在根内写入专用 tombstone 所有权标记，再把整个根原子改名为带 UUIDv7 的同级 tombstone，持久化父目录，建立带正式标记的新空根，最后删除旧 tombstone。
8. 启动只回收名称具有合法 UUID 且包含专用所有权标记的 tombstone。相似名称但没有标记的目录保持不变。进程在轮换后的任一点中断时，下一次启动均可建立或复用新空根，并回收已确认归属应用的旧目录。
9. 清理、维护和读取/写入通过同一进程锁协调；命令不接受缓存路径。所有报告只包含计数、字节、策略和解码器版本，不包含素材路径或用户元数据。

## 后果

- 缓存长期增长受条目数、字节数和年龄三重约束；短暂并发写入结束后会收敛到硬容量边界；
- 解码器升级不会要求删除仍兼容的当前版本条目；
- 素材移除或根目录变更后的缩略图在完整扫描收敛后自动回收；
- 强制终止清理只损失可重建缩略图，不会触及原图或 Sidecar；
- 每项增加一个小型 JSON 描述文件，并在命中时产生一次缓存 mtime 更新；
- 无数据库意味着维护需要遍历缓存目录，默认通过有界写入间隔与扫描完成时机控制成本。

## 拒绝的方案

- 使用 SQLite、IndexedDB 或单一权威清单维护 LRU；
- 把源路径、Tag、备注或稳定身份只存入缓存描述；
- 只改变缓存键但永久保留所有旧版本文件；
- 清理时直接递归删除活动缓存根；
- 根据名称前缀删除没有应用所有权标记的同级目录；
- 扫描进行中按不完整目录快照回收孤立条目。
