# ADR-032：生产交互状态、后端排序与可访问虚拟网格

- 状态：Accepted
- 日期：2026-08-20
- 对应：P3-07、P3-A10、P3-A11
- 实施门禁：阶段 2 退出后

## 背景

阶段 1 的按行窗口化已把 M 数据集 DOM 卡片限制在视口附近，并支持基础方向键、Home/End 和单一 4:3 卡片尺寸。P3-07 还要支持多种缩略图密度、排序、快速/全屏预览、命令面板、Tag 自动补全/规范化/重命名、统一任务状态和完整键盘路径。

若 React 单独排序或解析高级查询，桌面与 Rust 会出现两套结果语义；若虚拟化以当前 DOM 索引维持焦点，筛选、排序和扫描批次变化会让焦点跳到错误素材。Tag “规范化”若在扫描或打开 Sidecar 时静默执行，还会改写用户手工数据并破坏查询/保存过滤器。

## 决策

1. Rust catalog 是查询、scope、排序和 revision 的唯一正式执行者。查询响应返回固定有序键、catalog revision、总数和规范化 sort；React 只窗口化该序列，不按素材字段重新排序正式结果。
2. 排序字段与 ADR-027 的保存过滤器一致：文件名、修改时间、创建时间、文件大小、评分和素材类型，方向为升/降序。主字段相同或缺失时统一以运行时 key 升序决胜；缺失值在升/降序中都排在已知值之后。未使用保存过滤器时的当前 sort 可作为纯 UI 偏好写入 `application.yml`，不保存结果键。
3. 网格保留语义 `list/listitem + button`，使用 roving tabindex 维护唯一 tab stop。焦点身份使用 asset key，不使用 DOM 节点或裸数组索引；窗口卸载、列数变化和滚动后按 key 恢复。
4. 查询/排序变化后，若焦点 key 仍存在则保持；否则聚焦结果列表容器并朗读新计数，不猜测另一项。扫描移动映射只有稳定 ID 唯一时迁移焦点/选择。选择与范围动作继续使用 ADR-029 catalog revision。
5. 网格提供 `compact`、`comfortable`、`large` 三种稳定密度。容器宽度、字体缩放、系统缩放和实际卡片 chrome 由 `ResizeObserver`/测量模型计算列数与行高；单个素材标题不得让虚拟行高隐式变化。密度和当前 sort 属于 `application.yml` 用户偏好，不保存素材列表、选择或滚动位置；保存过滤器激活时使用其显式 sort，但不覆盖全局偏好。
6. 缩略图尺寸由可见卡片实际 CSS 像素 × devicePixelRatio 量化到协议档位并设 2,048 上限；只为视口/overscan 请求。密度、DPI 或 provider version 改变产生新的派生缓存键，旧项由现有生命周期回收。
7. Space 打开快速预览，Enter 打开检查器，显式命令进入全屏预览。预览按当前有序结果的前/后一项导航，保持 focus return key；Escape 关闭最上层界面。所有对象 URL、媒体句柄和 worker 请求在切换/关闭/卸载时释放或取消，不使用任意 `file://`。
8. 命令面板是静态注册表，不执行脚本、shell、URL 或任意 IPC。每个命令声明稳定 ID、标题、快捷键、可用条件、禁用原因和执行入口；搜索只过滤命令元数据。打开时焦点进入对话框，关闭后回到触发元素。
9. 新建 Tag 输入执行 NFC、去除首尾 Unicode 空白并拒绝空值、控制字符、`|` 与 `*`；保留内部空白、斜杠层级和大小写。扫描到的既有非规范 Tag 原样显示并标记为 legacy，绝不静默改写，仍允许精确移除或显式重命名。
10. Tag 自动补全只来自当前 catalog 的去重 Tag/计数，按前缀、最近明确使用和码点顺序确定；不联网、不读取笔记、不保存素材快照。选择补全不自动提交 Sidecar，Enter/按钮才形成编辑动作。
11. Tag 重命名必须指定精确旧 Tag、新规范 Tag 和明确根 scope，先预览受影响素材/冲突/保存过滤器。Sidecar 更新使用 ADR-020/029 事务；目标 Tag 已存在时按集合合并。ADR-027 的过滤器 AST 更新由用户逐项确认，外部变化停止未执行项。
12. 扫描、解码、Hash、批量事务、冲突、离线根和插件状态进入统一 task center。状态包含文本、图标和计数，不能只靠颜色；通知按稳定 task ID 更新，不能每个进度样本制造新的 live-region 消息。
13. 可访问性验收组合自动检查与人工屏幕阅读器/键盘矩阵。自动工具只能发现部分问题，不能替代 VoiceOver、Narrator 和至少一个 Linux AT-SPI 阅读器的真实关键路径。

## 影响

- 查询、排序、选择快照和保存过滤器共享后端唯一有序语义。
- 虚拟化节点生命周期不再决定焦点身份，筛选/缩放时不会误操作相邻素材。
- 三种密度可持久化，但滚动位置、选择和预览仍是可丢弃运行期状态。
- 新 Tag 具有可查询规范，既有非规范 Sidecar 不被打开即改写。
- P3-A10/A11 需要真实辅助技术和 L 数据集长时交互证据，单元测试或视觉截图不足以通过。

## 不采用

- 在 TypeScript 中复制查询或排序语义；
- 以 DOM index 作为持久焦点/选择身份；
- 因卡片标题变化产生未测量的可变虚拟行高；
- 为恢复滚动而保存素材结果快照；
- 扫描时自动 trim、改大小写或重写已有 Tag；
- 命令面板执行任意脚本、shell 或用户输入的命令名；
- 用自动 a11y 扫描替代屏幕阅读器和完整键盘人工检查。
