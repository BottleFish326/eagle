# 用户数据、缓存与恢复说明

Material Eagle 把数据分成三类。只有原素材和相邻 Sidecar 是素材真相源；应用配置可备份但不包含素材副本；缓存与内存索引可以随时重建。

## 1. 数据分类

| 类型         | 内容                                                          | 能否删除                           | 恢复方式                               |
| ------------ | ------------------------------------------------------------- | ---------------------------------- | -------------------------------------- |
| 原始素材     | 用户目录中的 PNG/JPEG/WebP/GIF                                | 不应由应用删除                     | 由用户自己的文件备份恢复               |
| 相邻 Sidecar | `<素材名>.asset.yml` 中的 ID、Tag、评分、收藏、备注、别名及可选素材指纹 | 不可当作缓存删除 | 与素材一起备份；应用扫描后重新解释 |
| 应用配置     | `application.yml`、`library-roots.yml`、`obsidian-vaults.yml` | 可删除，但会丢失授权列表与界面偏好 | 从备份恢复，或重新配置根目录/Vault     |
| 事务恢复日志 | `metadata-transactions-v1/*.transaction.yml` 中的批量计划、原/计划 Sidecar 内容与摘要 | 可显式删除，但会失去该批次的继续/恢复依据 | 从配置备份恢复；当前 Sidecar 不受删除日志影响 |
| 派生缓存     | `thumbnails-v1` 中的缩略图 PNG 与生命周期 JSON                 | 可以                               | 自动回收、设置页手动回收/重建，或重启后按需生成 |
| 运行期状态   | 素材目录、倒排索引、选择和查询结果                            | 可以                               | 重新扫描素材与 Sidecar                 |
| 运行期冲突计划 | 最近最多 256 项并发编辑的基线、外部值和用户补丁，仅在内存中 | 可以；退出应用即清除 | 重新扫描后再次执行需要的编辑 |
| 诊断导出     | `diagnostics/*.json`                                          | 可以                               | 需要支持信息时重新导出                 |
| 运行诊断日志 | `diagnostics/runtime/*.jsonl`，最多 5 个 1 MiB 分段           | 可以                               | 应用运行时自动重新建立                 |

## 2. 如何找到目录

点击顶部齿轮按钮打开“设置与恢复”，页面会显示当前平台实际使用的：

- 配置目录：包含三个可读 YAML 配置，以及需要时创建的 `metadata-transactions-v1` 恢复日志目录；
- 缓存目录：包含固定的 `thumbnails-v1` 派生缓存；
- 日志目录：诊断 JSON 导出到其 `diagnostics` 子目录。

这些位置由 Tauri 按应用标识 `dev.bottlefish.material-eagle` 和当前操作系统解析。以设置页显示的绝对路径为准，不要根据示例猜测目录。

## 3. 推荐备份

完整备份至少包括：

1. 原始素材目录；
2. 素材旁边的全部 `.asset.yml` Sidecar；
3. 设置页显示的配置目录。

无需备份缓存、内存索引或诊断导出。恢复后启动应用，它会从素材和 Sidecar 重新生成目录、索引与缩略图。

素材指纹包含字节数、采样 SHA-256 和完整 SHA-256，用于外部移动后的候选核对，不是素材副本。旧 Sidecar 没有指纹时仍能正常恢复 Tag；但在素材与 Sidecar 分离后，应用不会仅凭名称或大小猜测重新关联。

事务日志会暂时保存操作前和计划后的 Sidecar 完整内容，因此可能包含 Tag、备注和别名。它不是诊断导出，不应在未审阅时分享。已完成且不再需要恢复的日志可在“设置与恢复”中二次确认删除；`active` 或 `conflict` 日志建议处理完再删除。

单次并发编辑产生的字段级冲突计划不写入配置文件或数据库，只存在于当前进程的有界内存。同步工具创建的冲突副本则是素材根中的真实用户文件，应与其他 Sidecar 一起纳入备份；应用只诊断，不会自动删除、改名或合并。

## 4. 安全重建步骤

设置页会显示当前条目/20,000 上限、当前空间/1 GiB 上限、30 天保留周期和解码器版本。正常释放空间时，等待所有可用素材根至少完整扫描成功一次，再点击“立即回收无效缓存”；应用会移除旧解码器、孤立、过期和超容量条目，不清空仍有效的当前版本缩略图。扫描失败或取消时，孤立回收会等待而不是把不完整目录当作删除依据。

移动盘、网络盘或同步目录在扫描中掉线时，扫描前目录记录会保留，根配置不会被删除，缓存孤立回收也不会获得权威资格。恢复连接后先确认根状态回到“可用”，再执行完整一致性扫描；不要把离线时的运行期视图当作磁盘删除结果。

当缩略图异常、缓存升级或想验证完全可恢复性时：

1. 等待当前扫描结束，或在素材页停止扫描；
2. 打开“设置与恢复”；
3. 点击“清理缓存并重建”；
4. 再次点击确认；
5. 等待所有启用且可访问的素材位置重新扫描。

报告会显示移除的缓存文件、字节数和重建前的运行期素材数。该操作不修改素材、Sidecar 和三个 YAML 配置。如果执行失败，不要手工删除不确定的目录；先导出诊断日志并核对设置页显示的缓存路径。

## 5. 启动自动恢复

缓存布局使用版本标记。应用启动时遇到旧版标记，或固定缓存目录中存在无标记旧数据，会自动清空该固定目录并创建兼容缓存。兼容布局也会回收不完整、旧解码器、过期和超容量项。设置页会显示本次启动是首次创建、正常复用、启动维护、无标记重建还是版本不兼容重建。

清理不会在活动目录内逐个删除文件，而是先把完整缓存根轮换为带 UUID 和所有权标记的同级 tombstone，再立即建立新空根。若此时进程或系统中断，下一次启动只回收名称和所有权标记都匹配的 tombstone，然后按需重建缩略图；相似名称但没有标记的目录不会被删除。

如果缓存目录或标记是符号链接、普通文件等不安全形态，应用会拒绝自动清理并报告错误，避免误删链接目标。

## 6. 诊断日志的隐私边界

诊断导出包含构建、系统、配置计数、缓存统计、访问状态和最近最多 256 条结构化事件。它不包含素材/Vault 绝对路径、文件名、查询原文、Tag、备注、别名或 Sidecar 内容；授权路径只表示为匿名序号和短哈希指纹。

同样的路径无关事件会进入 `diagnostics/runtime` 的滚动 JSONL 日志，单文件最多 1 MiB、最多保留 5 个；绝对路径形式会在落盘前替换为短指纹。删除这些运行日志不影响素材目录，应用会按需重新建立。

分享诊断文件前仍建议按组织政策审阅 JSON。支持完成后可以直接删除导出文件，不影响应用功能。

## 7. 批量事务恢复

批量编辑两项以上素材时，应用会先在固定配置子目录写入完整计划，再逐项原子写入 Sidecar。应用中断后，下一次启动会提示发现待处理事务。打开“设置与恢复”后可以：

1. 选择“继续未完成项”：只写入当前仍保持操作前摘要、且素材指纹未变化的项目；
2. 选择“安全恢复”：只恢复当前仍保持本次计划摘要的项目；事务后被外部工具修改的 Sidecar 保持不变并显示冲突；
3. 选择“仅删除日志”：二次确认后只移除恢复依据，不改动任何素材或 Sidecar。

继续和恢复在素材根停用、不可访问、正在扫描、路径越出授权根或 Sidecar 路径异常时都会停止。操作完成后应用重新扫描受影响的可用素材根，使运行期目录与磁盘重新收敛。

## 8. 并发编辑与同步冲突

检查器中的并发冲突在解决前会重新核对 Sidecar 的修改时间、文件大小和 SHA-256。Tag 可显式合并集合差异；备注等整值字段必须选用外部或自己的版本。如果冲突面板打开后文件再次变化，解决会停止，需要重新扫描，任何外部内容都不会被旧计划覆盖。

素材根诊断中的 Dropbox、Syncthing 或通用冲突副本保持原路径和原字节。应用只在稳定 ID 能唯一对应普通 Sidecar 时显示字段差异；无法唯一对应时不按名称、时间或路径猜测。请先保留两份文件并结合同步工具历史人工判断，确认备份后再由用户在应用外处理。
