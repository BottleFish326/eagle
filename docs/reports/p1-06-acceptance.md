# P1-06 缩略图管线验收报告

> 验收日期：2026-08-14
>
> 验收状态：通过

## 1. 验收范围

本报告验收开发计划中的 P1-06：

- PNG、JPEG、WebP 和 GIF 第一帧缩略图；
- 由视口按需触发且解码并发有上限；
- 缓存键包含素材标识、路径、mtime、大小、尺寸和解码器版本；
- 原文件改变后旧缩略图不再命中；
- 损坏图片返回占位原因和错误信息；
- 清理或删除缓存后可重建，且不删除 Sidecar、不修改原始素材；
- Rust 核心、Tauri 命令和 TypeScript 调用协议完整连通。

实际素材网格、`IntersectionObserver`、占位视觉样式和对象 URL 生命周期属于 P1-07，不在本次验收范围内。

## 2. 实现结果

新增 `asset-preview` Rust crate，职责被分为解码、并发许可、缓存存取和稳定协议四部分。生成过程不在扫描器中运行；只有前端调用 `request_thumbnail` 才会读取并解码一个已进入内存目录的素材。

格式由文件内容识别，避免扩展名伪装。解码器支持 PNG、JPEG、WebP 和 GIF，GIF 固定使用第一帧；方向变换在缩放前应用，输出统一为 PNG。源图维度、解码内存和目标尺寸均有硬上限。

桌面命令使用阻塞任务池执行文件读取和解码，服务内部把同时解码数限制为 4。`read_thumbnail` 使用 Tauri 原始二进制响应，不经 JSON 数组中转。协议详见 `specs/thumbnail-protocol.md`，架构边界详见 ADR-013。

## 3. 缓存与失效

缓存位于操作系统应用缓存目录下的固定 `thumbnails-v1`，不进入任何素材根。64 位 SHA-256 键包含规范化运行时路径键、稳定 ID（若有）、源文件大小、mtime、请求长边和解码器版本；键前两位用于目录分片。

每次生成前后都会读取真实文件版本：排队期间发生变化会重新计算键，解码期间发生变化则丢弃结果并返回 `source-changed`。缓存命中还会验证 PNG 尺寸，损坏条目会被删除并重新生成。

缓存写入使用同目录临时文件、文件同步和原子持久化。清理命令不接受路径参数，并在排他锁下校验规范父目录、固定目录名、非符号链接和保护标记，然后只重建该缓存目录。

## 6. 数据安全结论

- 生成、命中、失效、清理和整目录删除重建都不写原始素材；
- 原图保护测试在操作前后计算 SHA-256，结果一致；
- Sidecar 不位于缓存目录，清理测试同时验证其字节内容不变；
- 缓存键、PNG 和内存目录均为派生数据，删除后不会丢失 Tag、备注、收藏、评分或稳定 ID；
- 前端只能按内存目录中的素材键请求生成，不能把任意文件路径送入解码器。
