## 1. 准备结论

P3-04 已固定“全选当前结果”的时间点语义、后端精确快照、范围选择 revision、批量预检、协作取消、事务续传和剪贴板单次提交边界。实现将复用 P2-03 的纯文件元数据事务和 P2-04 的版本冲突机制，不新增素材列表数据库或动态全选副作用。

## 3. 实施切片

### P3-04A：选择 session

- 为 catalog 增加单调 revision；
- 后端建立/释放/过期回收精确有序快照；
- UI 完成切换、范围和全选当前结果；
- 证明 100,000 键快照受控且不会落盘。

### P3-04B：只读预检

- 以 snapshot ID 解析当前记录；
- 唯一稳定 ID 移动收敛，删除/歧义/离线/撤权逐项报告；
- confirmation 绑定 operation ID、revision 和计数。

### P3-04C：可取消元数据事务

- 向事务执行循环接入 cancel token；
- 停止后立即检查点并返回 planned 计数；
- UI 显示继续、条件恢复和失败清单；
- 不改变单 Sidecar 原子写入协议。

### P3-04D：路径与引用输出

- 按快照顺序生成路径、Markdown、HTML 和稳定引用；
- 缺失 ID 走显式预检与元数据事务；
- 完整缓冲成功后单次写剪贴板；
- 失败项不得默认静默省略。

### P3-04E：1,000 项故障验收

- 固定提交边界取消和真实进程终止各一轮；
- 重启继续、条件恢复、外部修改保护；
- 检查新匹配项不进入旧快照；
- 记录时间、RSS、队列和素材哈希。

## 4. 通过条件

P3-A06 只有在 1,000 项自动化场景同时证明以下事实后通过：

- 全选集合在确认后不随扫描结果扩大；
- 取消后的 applied/planned/failed/conflict 计数与磁盘逐项审计一致；
- 未执行项原字节保持不变，已执行项是完整合法 Sidecar；
- 重启可发现、继续或条件恢复；
- 输出顺序稳定、失败可见、剪贴板不会得到半成品；
- 原始素材 SHA-256 全部不变；
- 选择快照、查询结果和输出内容没有落入数据库或不可清理缓存。
