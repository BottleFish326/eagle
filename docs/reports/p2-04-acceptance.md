## 1. 交付范围

本工作项完成以下链路：

- Sidecar 扫描、目录记录、单项编辑和批量事务统一传递 mtime、文件大小与 SHA-256 完整版本；
- 读取期间及原子替换前检测版本变化，同内容 mtime 变化也使旧观察失效；
- 乐观写入冲突后生成后端 UUIDv7 不透明计划，只在最多 256 项的运行期内存中保存；
- 以目录记录为编辑前版本、磁盘 Sidecar 为外部当前版本、原用户补丁为我的版本执行字段级分析；
- Tag 重叠修改提供集合增量合并、保留外部和使用我的三个显式选项；
- 备注、评分、收藏和别名重叠时逐项要求保留外部或使用我的，禁止自动拼接；
- 冲突界面显示来源、外部修改时间、变化字段及编辑前/外部当前/我的修改三组值；
- 解决前重新核对授权根、扫描互斥、路径范围和完整 Sidecar 版本；再次变化时停止；
- 一致性诊断识别 Dropbox、Syncthing 和保守通用 YAML 冲突副本，显示来源、时间、唯一原件和用户字段差异；
- 同步冲突副本没有删除、移动、改名或自动合并入口。

没有引入数据库、IndexedDB、LocalStorage 或权威冲突索引。Sidecar 和同步冲突副本仍是普通用户文件；冲突计划退出应用即丢弃，重新扫描以磁盘事实恢复。

## 2. 完整版本与写入边界

`SidecarFileVersion` 包含：

```text
digest              SHA-256 内容摘要
size                文件字节数
modifiedUnixMs      文件系统修改时间
```

扫描器把三项写入 `AssetRecord.sidecarState`，前端编辑目标完整回传，目录和批量事务再从当前记录构造后端期望版本。读取 Sidecar 时比较读取前后的大小、mtime 和实际字节数；写入继续执行两次期望版本校验，并在原子替换后确认磁盘内容仍等于计划摘要。任何不一致返回冲突，不更新运行期目录。

兼容核心函数仍允许旧调用者使用单独摘要；正式桌面单项与批量编辑链路均使用完整版本。P2-03 已落盘事务恢复仍以原/计划/当前内容摘要证明恢复条件，不把 mtime 当作内容证明。

## 3. 字段级显式解决

冲突分析只把“用户补丁触及、外部也改变、双方结果不同”的字段列为重叠冲突。解决从当前外部 Sidecar 克隆，因此保留外部稳定 ID、指纹以外的未知字段和未触及字段。

| 字段 | 重叠时允许的选择 | 行为 |
|---|---|---|
| Tag | 合并 Tag / 保留外部 / 使用我的 | 合并把相对编辑前版本的增加和删除意图应用到当前外部集合 |
| 评分 | 保留外部 / 使用我的 | 整值选择，不取较大值 |
| 收藏 | 保留外部 / 使用我的 | 布尔值选择 |
| 备注 | 保留外部 / 使用我的 | 整值选择，绝不自动串接文本 |
| 别名 | 保留外部 / 使用我的 | 整个集合选边，不静默并集 |

所有重叠字段选完才能提交。后端只接受不透明冲突 ID 和选择枚举，不接受客户端文件路径。每个素材的新冲突会使旧计划失效；解决或放弃记录不含路径、Tag、备注的结构化诊断事件。

## 4. 同步冲突副本诊断

诊断仅考虑文件名含 `.asset` 的 YAML/YML，并保守识别：

- Syncthing：文件名包含 `.sync-conflict-`；
- Dropbox：文件名包含 `conflicted copy` 和括号；
- 通用兼容：`conflict copy (...)`、`.conflicted.` 或 `-conflicted-copy`。

普通相邻 Sidecar 不会因上述诊断被排除或修改。冲突副本解析成功且稳定 ID 恰好对应一个普通 Sidecar 时，报告 Tag、评分、收藏、备注和别名的差异；原件缺失、相同 ID 原件不唯一或 YAML 损坏时只显示原因，不根据文件名、路径距离或 mtime 猜测。

## 7. 已知边界

- 冲突计划故意不持久化；应用退出后需重新扫描并再次发起编辑，不依赖私有恢复状态；
- mtime 按跨前端安全的 Unix 毫秒值传递，内容身份仍以 SHA-256 为准；
- 同步工具可能引入新的命名格式，当前策略宁可漏报也不把普通文件误判后自动处理；
- 同步冲突副本目前只做诊断，最终人工保留、改名或删除由用户在应用外完成；
- P2-05 已完成缩略图缓存容量、保留期限、精确失效和孤立项回收；A11/A12 外部门禁与 A04/A10 候选本地故障门禁均已通过。
