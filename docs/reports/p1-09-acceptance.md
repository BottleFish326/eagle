# P1-09 应用配置与可恢复性验收报告

> 验收日期：2026-08-14
>
> 验收状态：本地通过

## 1. 验收范围

本报告验收开发计划中的 P1-09：

- 使用普通 YAML 保存查询、Tag 三态与当前 Vault；
- 原子更新并保留未来未知字段；
- 启动时识别缺失或不兼容的缓存标记并安全重建；
- 提供二次确认的“清理缓存并重建”入口；
- 导出有界、路径脱敏的最小诊断 JSON；
- 说明用户数据、配置、缓存和恢复边界。

配置迁移、崩溃转储、磁盘容量回收和持久化扫描快照属于阶段 2，不在本次范围。

## 2. 核心实现

新增 `app-config` Rust crate 和 `schemas/application-config.schema.json`。`ApplicationConfigManager` 读取 `application.yml`，对单行查询、Tag 数量/长度和 UUID 执行验证，使用同目录临时文件、文件同步、原子持久化与父目录同步。更新只替换已知 UI 字段，未知顶层和 `ui` 字段继续保留；写入失败不会提前更新内存配置。

桌面启动并行读取应用配置、素材根、Vault 与恢复状态，然后恢复查询、Tag 三态和有效目标 Vault，再开始扫描。偏好以 500 毫秒去抖保存，不使用 LocalStorage、IndexedDB 或素材数据库。前端与 Tauri 新增五个稳定命令：

- `get_application_config`；
- `update_application_config`；
- `runtime_recovery_status`；
- `reset_derived_state`；
- `export_diagnostics`。

## 3. 缓存与重建边界

缩略图缓存标记现声明布局版本。启动结果区分首次创建、兼容复用、缺标记重建和版本不兼容重建；后两者只统计并重置固定 `thumbnails-v1`。缓存根、分片和标记的符号链接保护继续生效。

设置页只在无活动扫描时启用重建，并要求第二次点击确认。后端命令不接收路径，先重置经过标记校验的缩略图缓存，再清空运行期 `AssetCatalog` 与倒排索引；前端随后扫描全部启用且可访问的素材根。素材、Sidecar 和三个配置 YAML 都不在删除边界内。

## 4. 诊断边界

`DiagnosticService` 在内存保留最近 256 条事件，并在应用日志目录原子写入 Schema 1 JSON。导出包含构建、系统、配置计数、缓存统计、目录/扫描统计和匿名访问状态。绝对路径只在生成短 SHA-256 指纹时使用，不进入文件；查询只输出是否存在，Tag 只输出数量，文件名、备注、别名和 Sidecar 正文均不记录。
