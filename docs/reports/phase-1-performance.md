## 2. 自动门禁与判定阈值

`npm run test:medium` 在 `mkdtemp` 创建的隔离目录中生成 M 夹具，执行 Release 扫描和 200 次复合查询，验证原始素材 SHA-256 后只清理由当前进程创建且带夹具标记的目录。

`npm run test:stability` 启动独立 Vite 与 Chrome 进程，等待 10,000 项完成加载，预热 60 秒，再连续运行 30 分钟。运行期间每秒滚动，每 8 秒轮换以下查询，每 5 秒采集堆、DOM、卡片数和事件循环延迟：

| 查询                                         | 期望结果 |
| -------------------------------------------- | -------: |
| 空查询                                       |   10,000 |
| `favorite:true`                              |    3,750 |
| `color/blue`                                 |    2,500 |
| `any:(color/green\|color/red) -state/review` |    3,125 |

稳定性自动拒绝条件为：

- JavaScript 堆首尾增长超过 128 MiB；
- 堆线性趋势超过 4 MiB/分钟；
- 事件循环延迟 p95 超过 1,500 毫秒；
- Long Task 累计时长占比超过 35%；
- 同时挂载的素材卡片超过 120；
- 任一筛选结果数量错误、页面重载、浏览器退出或 CDP 调用超过 5 秒。

Long Task 占比用于识别持续主线程繁忙；本轮没有单独采集操作系统级进程 CPU 百分比，因此不把它表述为空闲 CPU 基线的替代数据。

## 5. 门禁暴露的问题与修复

第一轮非正式回归正确返回四种查询结果，但全部匹配项都被创建为 React 卡片，20 秒内 Long Task 占比达到 54.4%，不满足阶段要求。修复过程没有放宽门槛：

1. 按行窗口化素材网格，只挂载视口与上下三行 overscan，并保留完整集合的键盘与 ARIA 语义；
2. 演示适配器用键映射替代线性查找，并复用有限预览变体，避免反复生成大 Canvas；
3. Obsidian 引用只解析当前虚拟窗口与唯一选中的检查器素材，不再为完整筛选结果创建引用对象；
4. 把卡片上限、筛选精确计数、浏览器重载检测和 5 秒 CDP 超时固化为自动拒绝条件。

设计边界记录于 [ADR-017](../../specs/adr/017-virtual-asset-grid-window.md)。

## 6. 复现命令

```bash
npm run test:medium
npm run test:stability
```

稳定性脚本当前默认使用 macOS 的 Google Chrome 安装路径；可通过 `--chrome <path>` 指定其他 Chromium 可执行文件。测试失败和成功都会关闭独立 Vite/Chrome 进程并清理临时浏览器档案。

## 7. 结论

M 数据集扫描、查询、原始素材保护以及 30 分钟 UI 滚动/筛选稳定性均通过自动门禁。阶段 1 的规模验收没有发现崩溃、页面重载、明显堆泄漏、持续主线程繁忙或全量 DOM 增长，可以作为 P1-A12 的退出证据。
