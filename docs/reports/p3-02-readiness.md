## 1. 准备结论

P3-02 的语法兼容边界、字段类型、单位、缺失值、显示方向、跨平台路径语义、混合索引策略和独立查询预言机已经固定。实施可以直接按测试先行切片推进，不再需要在整数/浮点、时区、未知属性或验证器复用产品代码之间临时选边。

## 3. 实施切片

### P3-02A：共享值模型与纯解析器

- 增加整数单位、RFC 3339、宽高比分数和枚举解析；
- 保持版本 1 全部语料结果和错误偏移不变；
- 规范化范围并拒绝冲突，不执行任何文件写入。

验收：单元测试覆盖所有单位/边界/溢出/时区/冲突错误；版本 1 查询回归 100% 一致。

### P3-02B：AssetRecord 派生属性

- 扩展 `media` 可选结构并由扫描/格式 provider 填充；
- 计算 EXIF/视频旋转后的有效尺寸、方向和宽高比；
- 未知属性保持 `None`，不写入 Sidecar。

验收：删除缓存重扫恢复同样属性；原始素材和 Sidecar 摘要保持不变。

### P3-02C：混合查询执行

- 低基数字段集合索引；
- 数值、时间、比例和路径在候选集上求值；
- 更新/删除记录后不得残留旧字段命中。

验收：独立线性 oracle 与索引结果逐例一致；L 数据集 200 次正式组合查询 p95 不超过 100 ms，记录 RSS 增量。

### P3-02D：查询一致性验证器

- 实现 Schema 和跨项语义验证；
- 独立执行 oracle，不链接产品查询 crates；
- 驱动产品 CLI 并生成三方差异报告。

验收：至少 40 条 record、60 个合法用例、24 个无效用例；对故意注入的产品/expected/oracle 三类错误都能失败。

### P3-02E：桌面字段过滤器

- 文本栏展示结构化错误和 UTF-8 字节位置；
- 可视化条件编辑器只生成规范允许的谓词；
- 无效输入保留上一次合法结果；
- 键盘和屏幕阅读器可识别字段、操作符、单位和错误。

验收：文本与可视化编辑往返不改变 AST；错误不会被转换为零结果；P3-A10 关键键盘路径预备通过。

## 4. P3-A03 证据要求

只有以下证据同时存在才可通过 P3-A03：

1. 固定语料的 Schema 与语义验证通过；
2. oracle 线性结果等于提交的 `expectedKeys`；
3. 正式产品查询结果等于相同键集合；
4. 每个新增字段、缺失值和边界均有用例；
5. L 数据集正式组合查询达到统一 100 ms p95 基线；
6. 测试前后原始素材 SHA-256 完全一致；
7. 报告记录平台、构建提交、工具版本、语料摘要和完整失败列表。
