## 1. 验收范围

本报告验收开发计划中的 P1-05：

- 多个普通 Tag 默认按 AND 组合；
- 支持排除 Tag；
- 支持一个或多个同组 OR；
- 支持 `namespace/*`；
- 支持素材类型、扩展名和收藏过滤；
- 查询解析错误不会静默转化为空结果；
- 查询可以通过内存目录、Tauri 命令和 TypeScript API 完整调用。

名称、备注和全文搜索未列入 P1-05，当前不在验收范围内。

## 2. 查询协议

正式语法见 `specs/query-language.md`。代表性表达式如下：

```text
ui/* any:(color/blue|color/red) -state/draft type:image ext:png|jpg favorite:true
```

解析器先生成规范化 `AssetQuery`，再交给倒排索引执行。空查询合法并匹配全部素材；未知过滤器、非法字段值、错误通配符、错误 OR 组、未闭合引号和冲突收藏条件均返回结构化错误。

错误包含稳定类型、零基字节位置、相关 Token 和可显示消息。桌面命令把错误包装为 `parse` 或 `internal`，因此 P1-07 UI 可以直接在搜索栏呈现，不需要根据字符串猜测错误类型。

## 3. 索引实现

`AssetIndex` 维护以下可重建倒排项：

| 倒排项 | 来源 | 更新规则 |
|---|---|---|
| Tag | Sidecar 合并后的 `AssetRecord.tags` | upsert 时移除旧集合并添加新集合 |
| 类型 | MIME 推导的 `AssetRecord.kind` | upsert 时替换 |
| 扩展名 | 文件路径推导的 `AssetRecord.extension` | 统一小写后替换 |
| 收藏 | Sidecar 合并后的 `AssetRecord.favorite` | upsert 时替换 |

查询结果使用素材运行时键确定性排序。桌面 IPC 只返回键、规范化查询和目录总数，避免每次筛选重复传输完整 `AssetRecord`。所有状态都能由文件和 Sidecar 重新扫描得到，不存在权威数据库。
