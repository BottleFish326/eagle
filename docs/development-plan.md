# 文件系统素材管理器：开发计划与验收规范

> 文档状态：已批准并执行
>
> 版本：0.2.0
>
> 最后更新：2026-08-15
>
> 适用范围：桌面端素材管理器、共享核心模块、Obsidian 集成插件

## 1. 文档目的

本文档把产品设计拆解为可以开发、测试和阶段评审的工作包。每个阶段均包含：

- 阶段目标和边界；
- 必须完成的开发内容；
- 必须交付的代码、规范和测试资产；
- 可重复执行的验收用例；
- 阶段退出条件；
- 风险及阻断条件。

阶段验收采用“证据驱动”原则。功能演示只能作为补充，自动化测试报告、性能数据、文件哈希、故障注入记录和兼容性矩阵才是主要验收证据。

## 2. 产品不变量

以下约束适用于所有阶段。任何实现若违反其中一项，必须停止合并并重新评审设计。

1. **文件系统是真相源**：素材文件和 sidecar 元数据是可恢复产品状态的唯一依据。
2. **不使用权威数据库**：不得以 SQLite、LevelDB、IndexedDB 或其他数据库保存不可重建的素材状态。
3. **不重构素材目录**：扫描、打标、过滤和引用操作不得自动移动、复制、重命名或重新编码原始素材。
4. **不修改原始素材**：默认不向 EXIF、IPTC、XMP 或文件内容回写数据。
5. **索引可重建**：内存索引、缩略图和可选扫描快照均属于派生缓存，删除后不影响 Tag、备注、收藏和稳定 ID。
6. **视图扁平、存储不变**：目录结构由用户维护，桌面端把多个根目录中的素材解释为扁平素材集合。
7. **单文件故障隔离**：损坏素材或损坏 sidecar 只能影响对应素材，不能阻断整个素材库。
8. **Obsidian 优先使用标准引用**：素材位于 Vault 内时，生成标准 `![[vault-relative-path]]`；只有 Vault 外素材使用插件协议。
9. **操作可审计**：写入 sidecar、批量 Tag 修改和冲突恢复必须产生足够的结构化日志。
10. **默认离线**：核心扫描、索引、Tag、预览和 Obsidian 引用不依赖网络服务。

### 2.1 原始素材保护验收基线

所有会写入元数据的测试，都必须在操作前后计算原始素材 SHA-256。以下操作完成后哈希必须完全一致：

- 添加、删除、重命名 Tag；
- 修改评分、收藏、别名和备注；
- 生成或清理缩略图；
- 保存或删除过滤器；
- 生成 Obsidian 引用；
- 重建索引和一致性检查。

## 3. 目标系统边界

### 3.1 核心对象

```text
LibraryRoot      用户授权扫描的根目录
AssetFile        原始素材文件
AssetSidecar     与素材相邻的可读元数据文件
AssetRecord      运行时合并后的统一素材对象
DerivedIndex     可重建的内存倒排索引
PreviewCache     可删除的缩略图/波形/封面缓存
SavedFilter      保存的查询表达式，不保存素材副本
ObsidianRef      Vault 内标准路径引用或 Vault 外稳定 ID 引用
```

### 3.2 Sidecar 约定

素材 `logo.png` 对应 `logo.png.asset.yml`。Sidecar 建议最小结构如下：

```yaml
schema: 1
id: "0198a7c2-8341-7a31-b842-f15d39f33c18"
tags:
  - ui/icon
  - project/eagle
rating: 4
favorite: true
note: "导航栏候选图标"
aliases:
  - main-logo
updatedAt: "2026-08-14T12:30:00+08:00"
```

规则：

- `id` 使用 UUIDv7 或 ULID，生成后不可因路径变化而改变；
- 无用户元数据且无需稳定引用的素材允许没有 sidecar；
- Sidecar 采用确定性序列化，字段顺序和换行风格保持稳定；
- 写入使用同目录临时文件加原子替换；
- 未识别字段必须保留，便于向前兼容和手工扩展；
- 解析失败时保留原文件，禁止用默认值覆盖损坏内容。

### 3.3 推荐代码模块

```text
apps/desktop/                    桌面 UI 与桌面壳
crates/asset-core/               统一素材模型
crates/filesystem/               扫描、路径规范化与文件监听
crates/metadata/                 Sidecar、原生元数据与版本迁移
crates/index/                    内存倒排索引与查询执行
crates/preview/                  缩略图和媒体预览
crates/link-resolver/            稳定 ID、Vault 路径和引用解析
crates/app-config/               可读应用偏好、诊断与恢复状态
integrations/obsidian-bridge/    Obsidian 桌面插件
schemas/                         Sidecar 与库配置 Schema
fixtures/                        固定测试素材
specs/                           架构决策和协议文档
tests/                           集成、端到端和性能测试
```

若最终采用其他技术栈，可以调整目录，但模块职责和依赖方向不得反转：UI 不得直接承担文件扫描、Sidecar 写入或引用解析。

## 4. 统一测试与验收规则

### 4.1 测试数据集

必须提供可重复生成的合成数据集，生成器只用于测试目录，禁止指向真实用户目录。

| 数据集 | 素材规模 | 用途 |
|---|---:|---|
| S | 1,000 | 日常功能和 CI 集成测试 |
| M | 10,000 | 回归测试、监听风暴和批量写入 |
| L | 100,000 | 性能、内存和长时间稳定性 |

测试数据至少覆盖：

- ASCII、中文、日文、Emoji、空格和超长文件名；
- 深层目录、同名文件、大小写差异路径；
- 只读目录、权限撤销、符号链接和循环链接；
- 零字节文件、扩展名伪装、截断文件和损坏 sidecar；
- 同内容不同路径、同文件名不同内容；
- 素材存在但 sidecar 缺失、sidecar 存在但素材缺失；
- 文件在扫描期间创建、修改、移动和删除；
- Git、网盘同步工具常见的临时文件和冲突副本。

### 4.2 性能基线

测试报告必须记录操作系统、CPU、内存、磁盘类型、文件系统和构建版本。初始目标如下；如需调整，必须通过架构决策记录说明原因和新基线。

| 指标 | 初始目标 |
|---|---:|
| L 数据集首次可交互首屏 | 不超过 3 秒 |
| L 数据集完整扫描 | 不超过 60 秒 |
| 100,000 条记录的 Tag 过滤 p95 | 不超过 100 毫秒 |
| 单次文件变化反映到 UI 的 p95 | 不超过 2 秒 |
| 100 个素材批量 Tag 写入 | 不超过 3 秒 |
| L 数据集稳定状态内存 | 不超过 1 GiB |
| 空闲状态 CPU | 平均低于单核 2% |

“首屏可交互”指用户能够查看已发现素材、滚动和执行搜索；不要求完整扫描结束。缩略图必须懒生成，不能成为首屏阻塞条件。

### 4.3 平台矩阵

每个发布候选版本至少覆盖：

- macOS：当前支持的主版本；
- Windows：当前支持的主版本，覆盖 NTFS；
- Linux：一个主流发行版，覆盖 ext4；
- Obsidian：当前稳定版和上一稳定版；
- 中文路径和英文路径各一套 Vault；
- 本地 SSD 为强制项，网络盘和同步盘为兼容性观察项。

### 4.4 通用完成定义

一个工作项只有同时满足以下条件才可标记完成：

- 代码通过格式化、静态检查和单元测试；
- 新行为包含自动化测试；
- 错误路径包含用户可理解的提示和结构化日志；
- 不变量测试通过，原始素材哈希未变化；
- 文档、Schema 和测试夹具同步更新；
- 不产生不可删除的缓存状态；
- 至少一名非实现者完成代码评审；
- 验收证据附在阶段报告中。

## 5. 阶段 0：技术验证与架构定案

### 5.1 阶段目标

在进入产品开发前，验证最危险的技术假设，并以架构决策记录固定关键边界。此阶段允许使用命令行原型和简陋界面，但结果必须可重复。

### 5.2 开发内容

#### P0-01：需求约束与架构决策记录

完成以下 ADR：

- ADR-001：文件系统真相源与“无权威数据库”定义；
- ADR-002：相邻 sidecar 命名、Schema、ID 和版本迁移；
- ADR-003：派生缓存允许保存的内容和清理规则；
- ADR-004：文件移动、孤立 sidecar 与重新关联策略；
- ADR-005：Vault 内标准引用与 Vault 外插件协议；
- ADR-006：桌面技术栈及平台支持范围；
- ADR-007：符号链接、网络盘和同步目录策略；
- ADR-008：外部素材在 Obsidian 中的安全渲染方案。

#### P0-02：测试素材生成器

- 可生成 S、M、L 三种规模数据；
- 能注入损坏文件、冲突 sidecar、权限问题和目录循环；
- 输出固定随机种子和数据清单；
- 提供清理保护，只允许删除生成器创建且带标记的目录。

#### P0-03：增量扫描原型

- 多根目录遍历；
- 路径规范化和忽略规则；
- 扩展名初筛加 MIME/文件头验证；
- 扫描结果增量输出；
- 单文件解析失败隔离；
- L 数据集性能和内存测量。

#### P0-04：内存索引与查询原型

- 建立 `tag -> assetId set` 等倒排索引；
- 支持包含、排除、AND、OR 和 Tag 命名空间；
- 比较集合实现方案的时间和内存；
- 验证 100,000 条记录下的查询延迟。

#### P0-05：Sidecar 写入与冲突原型

- 确定性序列化；
- 同目录临时文件和原子替换；
- 写入前版本检查；
- 模拟写入中断、磁盘满、权限撤销和外部并发编辑；
- 保留未知字段；
- 验证原始素材哈希不变。

#### P0-06：文件监听原型

- 创建、修改、删除和重命名事件；
- 事件去抖和合并；
- 监听溢出后回退到局部或完整扫描；
- 批量复制 10,000 个文件时不崩溃、不无限占用内存；
- 记录 macOS、Windows、Linux 的行为差异。

#### P0-07：Obsidian 联动原型

完成两条最小链路：

1. Vault 内图片生成 `![[relative/path.png]]` 并正常渲染；
2. Vault 外图片通过暂定 `material://<asset-id>` 语法由桌面插件解析并渲染。

外部渲染原型必须验证：

- 插件只能访问用户授权根目录；
- ID 解析后必须再次校验规范化路径；
- 不接受引用中直接传入任意绝对路径；
- 素材管理器未运行时的行为；
- 大文件渲染是否需要流式代理，以及对象 URL 的释放策略。

### 5.3 阶段交付物

- `specs/adr/` 下的 ADR-001 至 ADR-008；
- Sidecar 和库配置 Schema 初稿；
- 数据生成器及固定随机种子；
- 扫描、索引、监听、写入和 Obsidian 原型；
- 三平台差异记录；
- L 数据集性能报告；
- 技术风险清单和阶段 1 估算依据。

### 5.4 验收用例

| ID | 操作 | 期望结果与证据 |
|---|---|---|
| P0-A01 | 删除所有缓存后扫描 S/M/L 数据集 | 记录数与清单一致，无数据库依赖，失败文件被单独报告 |
| P0-A02 | 对 100,000 条记录执行 1,000 次混合 Tag 查询 | p95 达到性能基线，结果与朴素遍历结果完全一致 |
| P0-A03 | 在 Sidecar 替换前、中、后强制终止进程 | 原 Sidecar 或新 Sidecar至少一个完整可读，不出现半文件 |
| P0-A04 | 写入前由外部编辑器修改同一 Sidecar | 检测冲突并停止覆盖，用户能选择重载或合并 |
| P0-A05 | 批量创建、移动、删除 10,000 个文件 | 最终模型与完整重新扫描结果一致，无持续内存增长 |
| P0-A06 | 在 Vault 内插入图片 | 生成标准引用，关闭自定义插件仍可渲染 |
| P0-A07 | 在 Vault 外插入图片 | 插件按稳定 ID 渲染，不在 Vault 中复制素材 |
| P0-A08 | 构造路径穿越和伪造 ID | 插件拒绝访问授权根目录之外的文件并记录安全事件 |

### 5.5 退出条件

- 八项 ADR 均已评审并处于 Accepted 状态；
- P0-A01 至 P0-A08 全部通过；
- 性能达到基线，或已有被批准的新基线 ADR；
- Obsidian 外部渲染技术路线已经定案；
- 没有未处理的“可能修改原始素材”风险；
- 阶段 1 的模块接口、工作拆分和测试策略已明确。

### 5.6 阻断条件

以下任一情况发生时不得进入阶段 1：

- 文件监听无法通过一致性扫描恢复；
- Sidecar 写入存在已知截断或静默覆盖风险；
- Vault 外渲染需要开放任意文件读取；
- 100,000 条数据必须依赖权威数据库才能满足基本交互；
- 删除缓存后无法完整恢复用户元数据。

## 6. 阶段 1：端到端最小可用版本

### 6.1 阶段目标

交付第一条完整用户链路：添加目录、浏览图片、编辑 Tag、按 Tag 筛选、生成 Obsidian Vault 内引用并成功渲染。

本阶段正式支持 PNG、JPEG、WebP 和 GIF。Vault 外自定义引用保留技术原型，不作为本阶段发布承诺。

### 6.2 开发内容

#### P1-01：项目骨架与持续集成

- 建立桌面端、核心模块、Schema、测试和插件目录；
- 配置格式化、静态检查、单元测试和构建任务；
- CI 使用 S 数据集执行跨模块集成测试；
- 生成包含版本、提交号和构建环境的信息。

#### P1-02：素材库根目录管理

- 添加、移除和临时停用根目录；
- 记录授权状态、显示名称和忽略规则；
- 检测重复根、父子重叠根和不可访问目录；
- 移除根目录只移除应用配置，不删除素材及 sidecar。

#### P1-03：正式扫描器与素材模型

- 增量扫描和取消；
- 统一 `AssetRecord`；
- 读取路径、类型、尺寸、时间、文件大小和原生只读元数据；
- 合并 sidecar，并明确字段优先级；
- 单文件错误状态在 UI 中可见。

#### P1-04：Sidecar 元数据编辑

- 首次编辑时生成稳定 ID 和 sidecar；
- 添加、删除和批量设置 Tag；
- 编辑评分、收藏、备注和别名的最小接口；
- 原子写入、冲突检测和错误恢复；
- Tag 修改后立即更新内存索引。

#### P1-05：Tag 查询引擎

- 默认多 Tag 为 AND；
- 支持排除 Tag；
- 支持同组 OR；
- 支持 `namespace/*`；
- 支持类型、扩展名和收藏过滤；
- 查询解析错误不得导致结果静默为空。

#### P1-06：缩略图管线

- PNG、JPEG、WebP 和 GIF 首帧；
- 按视口懒生成和并发限流；
- 缓存键包含素材标识、mtime、大小和解码器版本；
- 原文件变化后缩略图失效；
- 损坏图片显示占位和错误信息；
- 清理缓存不删除任何 sidecar。

#### P1-07：桌面端最小 UI

- 根目录管理页；
- 扁平素材网格；
- Tag 面板和三态筛选；
- 搜索栏和当前过滤条件；
- 素材检查器；
- 多选与批量 Tag；
- 扫描进度、空状态、权限错误和损坏文件状态；
- 键盘导航和基础可访问性。

#### P1-08：Obsidian Vault 内引用

- 配置一个或多个 Obsidian Vault 根路径；
- 判断素材是否位于目标 Vault；
- 生成 URL 编码正确的 Vault 相对路径；
- 支持复制 `![[path/to/image.png]]`；
- 支持从素材网格拖入 Obsidian；
- 同名文件必须生成包含目录的无歧义路径。

#### P1-09：应用配置与可恢复性

- 应用配置使用可读文件保存；
- 配置写入同样采用原子替换；
- 提供“清理缓存并重建”入口；
- 启动时发现缓存版本不兼容则自动丢弃并重建；
- 提供最小诊断日志导出。

### 6.3 阶段交付物

- 可安装的桌面开发构建；
- PNG/JPEG/WebP/GIF 扫描与预览；
- Tag 编辑和布尔过滤；
- Vault 内引用复制与拖放；
- Sidecar Schema v1；
- 用户数据目录和缓存目录说明；
- 单元、集成和端到端测试；
- MVP 操作说明与已知限制。

### 6.4 验收用例

| ID | 操作 | 期望结果与证据 |
|---|---|---|
| P1-A01 | 新安装后添加包含 1,000 张图片的目录 | 增量出现图片，数量正确，目录未被移动或复制 |
| P1-A02 | 给 20 张图片批量添加两个 Tag | 生成或更新对应 sidecar，素材哈希全部不变 |
| P1-A03 | 组合包含、排除和 OR 条件 | 结果与测试清单一致，过滤状态清晰可见 |
| P1-A04 | 重启应用 | Tag、评分和收藏恢复，索引由文件重新构建 |
| P1-A05 | 删除整个缓存目录后重启 | 功能状态完整恢复，只重新生成派生数据 |
| P1-A06 | 修改原图片内容但保留文件名 | 尺寸/mtime 更新，旧缩略图失效并重新生成 |
| P1-A07 | 打开损坏图片和损坏 sidecar | 单个素材显示错误，其他素材仍可浏览和筛选 |
| P1-A08 | 从 Vault 内素材复制并粘贴引用 | 生成标准 `![[...]]`，Obsidian 正常渲染 |

![[Materials/logo.png]]

| ID | 操作 | 期望结果与证据 |
|---|---|---|
| P4-A01 | 插入当前 Vault 内素材 | 生成标准 `![[...]]`，关闭插件后仍正常渲染 |
| P4-A02 | 插入 Vault 外素材 | 生成稳定 ID 引用，不复制素材到 Vault |
| P4-A03 | 关闭桌面素材管理器后重启 Obsidian | 插件通过文件系统最小索引继续解析外部引用 |
| P4-A04 | 将外部素材和 sidecar 一起移动到另一授权根 | 原 Markdown 不变且继续渲染 |
| P4-A05 | 删除或断开外部素材 | 显示丢失占位和修复入口，不修改笔记原文 |
| P4-A06 | 从 Obsidian 搜索 `ui/icon` 并多选插入 | 搜索结果准确，插入顺序正确，操作可撤销 |
| P4-A07 | 从引用打开桌面端 | 桌面端打开并选中正确素材 |
| P4-A08 | 从桌面端查看反向引用 | 列出的笔记与独立 Markdown 扫描结果一致 |
| P4-A09 | 构造伪造 ID、路径穿越、符号链接逃逸 | 访问被拒绝，授权根外文件不可读取 |
| P4-A10 | 在插件设置中移除某个授权根 | 该根的外部引用停止解析，其他根不受影响 |
| P4-A11 | 禁用和卸载插件 | Markdown、素材及 sidecar 均保持原样 |
| P4-A12 | 在两版 Obsidian 和中英文 Vault 执行核心链路 | 搜索、插入、渲染、跳转结果一致 |
| P4-A13 | 在移动端打开含两类引用的笔记 | Vault 内引用正常；外部引用按文档说明降级，不造成数据修改 |

### 9.6 退出条件

- P4-A01 至 P4-A13 全部通过；
- 插件安全评审无未解决的高风险问题；
- 当前稳定版和上一稳定版 Obsidian 兼容测试通过；
- 桌面应用运行与未运行两种模式均有明确行为；
- 插件禁用、卸载和授权撤销不会修改用户文件；
- 外部引用的可移植性和移动端限制已在插入时及文档中说明。

## 10. 发布门禁

阶段 4 完成后，首个公开版本还必须通过以下发布门禁。

### 10.1 数据安全门禁

- 所有原始素材保护测试通过；
- 30 次随机故障注入未产生截断 sidecar；
- 删除应用、缓存和配置后，原始素材及 sidecar 可直接使用；
- 没有默认永久删除操作；
- 所有批量写入都有失败清单和恢复路径。

### 10.2 质量门禁

- 单元测试、集成测试、端到端测试全部通过；
- 核心模块达到团队约定的覆盖率，关键写入路径必须分支覆盖；
- S 数据集进入每次 CI，M 数据集进入每日回归，L 数据集进入发布回归；
- 高优先级缺陷为零；
- 中优先级缺陷均有明确规避方式和后续计划。

### 10.3 性能门禁

- 统一性能基线全部通过；
- 三平台各有一份发布候选性能报告；
- 8 小时稳定性测试通过；
- 后台扫描、预览和 Obsidian 插件没有无界资源增长。

### 10.4 文档门禁

- 安装、升级、卸载和数据位置说明；
- Sidecar Schema 和迁移说明；
- 支持格式矩阵；
- Obsidian Vault 内/外引用差异；
- 备份、同步、符号链接和移动端限制；
- 故障恢复、冲突处理和诊断日志说明；
- 隐私与权限说明。

## 11. 需求—阶段追踪矩阵

| 核心需求 | 阶段 0 | 阶段 1 | 阶段 2 | 阶段 3 | 阶段 4 |
|---|---|---|---|---|---|
| 无权威数据库 | ADR 与性能验证 | 正式实现 | 恢复与缓存验证 | 高级功能保持可重建 | 插件不得成为第二真相源 |
| 不重构原始素材 | 原型验证 | MVP 不变量测试 | 外部移动与故障恢复 | 拖放、重复分析保护 | 插入引用不复制素材 |
| 扁平素材视图 | 索引原型 | 基础窗口化素材网格 | 增量一致性 | 动态网格、排序与预览 | Obsidian 搜索选择器 |
| Tag 与过滤 | 查询原型 | 基础 Tag 和布尔过滤 | 冲突、事务和恢复 | 高级查询与保存过滤器 | 插件内 Tag 搜索 |
| Obsidian 联动 | 两类引用原型 | Vault 内标准引用 | 引用相关路径恢复基础 | 统一拖放输出 | 完整插件和双向定位 |
| 数据安全 | 写入故障实验 | 原始哈希保护 | 崩溃、同步和权限恢复 | 格式与批量安全 | 插件权限和路径安全 |

## 12. 阶段评审流程

每个阶段按以下流程关闭：

1. 阶段负责人提交交付物清单和版本号；
2. 测试负责人执行该阶段全部验收用例；
3. 性能负责人提交与上一基线的差异报告；
4. 数据安全检查确认原始素材保护与 sidecar 完整性；
5. 产品负责人演示阶段目标对应的端到端链路；
6. 评审会议逐项确认退出条件；
7. 未通过项形成缺陷或新的 ADR，不得口头豁免；
8. 所有退出条件满足后，阶段状态改为 Accepted；
9. 下一阶段开始前冻结相关 Schema 和接口版本。

阶段报告建议使用以下模板：

```markdown
# 阶段 N 验收报告

- 构建版本：
- 提交号：
- 测试平台：
- 数据集版本：
- 验收日期：

## 交付物

## 验收用例结果

## 性能结果

## 原始素材哈希检查

## 未解决缺陷

## ADR 变化

## 退出结论
```

## 13. 缺陷优先级

| 级别 | 定义 | 阶段退出要求 |
|---|---|---|
| P0 | 原始素材丢失/被修改、任意文件读取、不可恢复元数据损坏 | 必须立即停止发布并修复 |
| P1 | 核心链路不可用、静默错误引用、批量操作无法恢复 | 阶段退出前清零 |
| P2 | 有规避方式的功能错误、明显性能回退 | 评审并制定明确修复版本 |
| P3 | 文案、轻微视觉或低频兼容问题 | 可进入后续计划 |

## 14. 决策收敛登记表

原“阶段 0 待定问题”不得在已决议后继续显示为开放，也不得把后续阶段的决定伪装成已经完成。当前状态如下：

| 决策 | 状态 | 权威依据 / 截止门禁 |
|---|---|---|
| 桌面技术栈 | Resolved | Tauri 2 + Rust + React/TypeScript/Vite；见 [ADR-006](../specs/adr/006-desktop-technology-stack.md) |
| Sidecar 格式与手工编辑 | Resolved | UTF-8 YAML、JSON Schema、保留未知字段和原子写入；见 [ADR-002](../specs/adr/002-sidecar-format-and-identity.md) |
| 稳定 ID | Resolved | UUIDv7；见 [ADR-002](../specs/adr/002-sidecar-format-and-identity.md) |
| 扫描快照 | Resolved for current release | 当前不持久化扫描快照；若未来增加，只能是可删除、可重建且不含用户状态的派生缓存；见 [ADR-003](../specs/adr/003-derived-cache-policy.md) |
| Vault 外渲染传输 | P4 decision required | UUID、授权根、realpath、MIME 和生命周期边界已由 [ADR-008](../specs/adr/008-external-asset-rendering-security.md) 固定；对象 URL 与受限流式代理的最终选择必须在 P4-04 实现前形成补充 ADR |
| 桌面应用未运行时的稳定 ID 解析 | Contract resolved; implementation pending | 插件从授权根和 Sidecar 建立可重建最小索引；见 [ADR-005](../specs/adr/005-obsidian-reference-strategy.md)，具体索引与性能在 P4-02 前定案 |
| 视频、音频、PDF 格式与 codec | Architecture resolved; packaging pending | 能力分层、worker 隔离和降级已由 [ADR-026](../specs/adr/026-capability-based-extended-format-pipeline.md) 固定；三平台依赖打包在 P3-01C 至 P3-01F 分片逐项关闭 |
| 保存过滤器作用域 | P3 decision required | 必须在 P3-03 实现前决定单库文件或用户级配置，并形成 ADR 与 Schema；不得先写隐式持久化 |
| 文件移动与删除 | Resolved for first public release | 应用只解释文件系统，不提供源素材移动或删除；重复分析只报告候选。未来若增加，必须单独 ADR、默认关闭，删除使用系统废纸篓 |
| 最低操作系统版本 | Release decision required | 在三平台安装包和原生能力矩阵稳定后、首个发布候选前固定，并写入安装与兼容文档 |
